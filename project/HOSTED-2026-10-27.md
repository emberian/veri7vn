# Shared Oracle hosting

Ember resumed the appliance work after the prior checkpoint and asked for an
efficient hosted service for dozens of users and agents. The objective is one
shared, admitted Oracle grain with bounded resident computation and separate
tenant state, plus completion of the real agent lifecycle and recovery path.

## Design being implemented

The existing runtime/data image is shared. Mini projects a tenant key from the
source-inspected principal and application/session coordinates into its RPC
session. The bridge sends that key on private loopback; caller-provided request
and conversation IDs cannot select a tenant. Each tenant has its own disk
workspace and request journal. A bounded pool starts isolated Oracle workers
on demand and retires idle workers before starting replacements. Busy capacity
returns a retryable refusal, without an unbounded queue or silent execution.

The current class-L grain has a 2 GiB budget, so its initial pool configuration
is one resident worker, with up to 128 persistent tenant workspaces. Larger
worker counts are operator choices that must be paired with a measured memory
budget. The pool supports testing two workers; that does not establish that two
fit class L. Measure Linux PSS/private memory and cgroup use as well as RSS:
shared file pages must not be counted as a private copy for every process.

Actual restart testing found that Oracle loses some conversational context when
its process exits despite preserving request results. Exact old requests must
still replay without starting a worker. A new turn in an evicted conversation
must return `conversation_reset_required`; the caller explicitly starts a new
conversation and supplies needed context. No automatic replay reconstructs
state. This is an explicit current limitation, not seamless conversation
persistence. Arbitrary tenant-supplied Python is not supported by this profile;
separate worker processes do not sandbox hostile same-UID code.

## Progress and parallel correctness work

The pool and private HTTP integration are committed in `32f5498`, with stale
conversation admission and legacy-journal guards in `c171f6f`. The scoped tenant
suite passes 31 tests. Mini commit `30268be0` adds the authenticated source-session
binding, browser page and bounded launcher. A real Linux U6-v2 Engine/fd3 run
passed query, tenant separation, exact replay, conflict and restart checks;
the retained Mini admission/recovery journey remains separate and incomplete.

The first 32-tenant Linux harness failed at shutdown because it signalled its
wrapper instead of the adapter. Its owned adapters were subsequently stopped
and verified gone. A read-only journal inspection substantiates 32 separate
tenant journals with completed identical request IDs and distinct replies;
lost in-memory timing observations are not qualification evidence. A subsequent
run retained two-worker measurements and a separate successful restart check:
exact replay and a stale-conversation refusal start no Engine. The focused
measurement run also encountered a process-sampling race; see the
[measurement report](../tools/usage/tenancy/MEASUREMENTS.md) for the usable
observations and limits. Neither failed run is a complete load-test pass.

Recovery attempt R2 installed the qualified native runtime and public listener,
then refused before birth because its reservation guard expected a nonexistent
top-level `target` field. The actual signed query projects identity as
`grain.task`. The retained signed parent matches the original witness exactly;
Store files remain unchanged, reserve one remains held, and no result or ACK
exists. The corrected guard retains every root and state comparison and adds a
regression through the actual query producer. The stopped R2 result is retained
at `/build/lanes/oracle-foreground-recovery-r2/final-result.json`, SHA256
`3e2f5abf64d9bb144d5813c48007084599e2f576b33691a3695b4d46013d4e21`.
The repaired runtime needs its own reviewed continuation plan.
