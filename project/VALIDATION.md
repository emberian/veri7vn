# Validation and evidence scope

Evidence qualifies exact captured inputs and consumers. A passing historical
receipt does not qualify newer source; a component pass does not establish its
parent workflow. [tasks.json](tasks.json) records current work. Formal closure and
trusted boundaries are tracked in [PROOF_OBLIGATIONS.md](PROOF_OBLIGATIONS.md).

## Running baseline

The captured standalone macOS ARM64 package supports outside-checkout source
import/reopen, exact native arithmetic, fresh-process recovery and browser source
editing. The [standalone record](../tests/deployment/evidence/standalone-aae0d7dd.json)
identifies its finite checks. Browser Workshop exercised import, exact Open, two
new-revision Saves, normal close and fresh CLI readback. Source Save preserves a
revision; it does not activate edited behavior. Current Workshop/native service
source contains newer unqualified changes.

Actual packaged generation `40ac45e74c0be18732a81bff246817cfb2cbe9de91abfc7c8a7ccfc234ec98bd`
ran public Main in two processes against the same nonempty workspace: sum then
product, exit zero, 59.053s and 21.354s including startup. The supervising harness
was interrupted before its terminal receipt; subprocess results remain evidence
for those calls, not a clean wrapper pass. Later D44 deployment `db6edb9e17021542dd1f0617f44630e194c952dd315b5124ccab4a72e8fd3cac`
adds the qualified resident lifecycle path below.

## Performance and deployment limits

The [installed pilot](../benchmarks/envelope/public-runtime-40ac-pilot.json)
records fresh/restart first answers at 22.823s/14.792s and two warm arithmetic
requests at 241.649ms/152.812ms. These individual observations on old40ac are not
p95 budgets, throughput evidence or current-source results. The public measurement
harness checks exact output, pinned generation, timeout and descendant pipe-drain
ownership; harness reliability is separate from application speed.

The [source attribution baseline](../benchmarks/envelope/standalone-b4ce-phase-baseline.json)
measured reopen at 22.005s, including 20.059s verification, 16.504s inventory and
14.371s nested aggregate hashing of 24,561 files/2.715GB. Timings overlap and clocks
differ. Used heap includes unreclaimed objects. These data selected invocation-local
hash-buffer reuse and standard lowercase HexFormat without skipping verification.

The [full-verification comparison](../benchmarks/envelope/standalone-hash-repair-comparison.json)
records reopen 22.005s→8.027s, verification 20.059s→7.246s and nested hashing
14.371s→3.776s with identical nonbootstrap inventory and exact 50-byte reopen output.
Twenty-nine verifier parity cases and ten shell checks passed, including partial
buffer tails and tampering. This is one fixed-order comparison with uncontrolled
cache/load, not native speedup, live-memory improvement or promoted release.

Runtime_Foundation saved in `1dc017e3eca640b784cc90ffda2b1a9c` (5m08);
a later service failure reused it in 17s. This is compiler-iteration evidence.
Accidental repeated builds and broad closure invalidation are engineering costs,
not reasons to launch competing native processes.

D51 upgrade qualification remains separate from same-generation restart. Old40ac
shared-input rows differ from D44 exact restoration. Preserve previous selection
and original state; do not normalize stored dependencies by ID or overwrite a
failed checkpoint. Clean install/rebuild, Linux x86_64, redistribution/license
closure and independent recipient trial remain open release gates.

## Recording a new result

Record exact target, source/control closure, receipt/log and required markers;
inspect the native statement and actual consumer, not only wrapper exit status.
Separate selected-child outcomes from unrelated batch failures and preserve input
instability honestly. State workload/toolchain and startup, admission, execution,
search, evidence, memory/I/O attribution. Current receipts supersede scope claims
only after their changed consumers run. Keep transient corpora/heaps out of commits.
