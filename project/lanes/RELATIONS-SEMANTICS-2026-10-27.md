## Reproduced

Run `python3 tools/usage/relation-audit-semantics/test_semantics.py`: **4 tests passed**. The test inputs preserve every original row when completing the unknown data; they show that both completions are consistent with the original evidence.

1. An inverse actress question has two fetched spouses, one with actor occupation and female P21, and another with actor occupation but no P21. The kernel answers the first. Adding female P21 to the second changes its result to `ambiguous`. `complete=True` establishes that all *stored* rows were retrieved, not that the second person is not female. Likewise, with an inverse actor question, a second spouse with no stored occupation is filtered out; adding actor occupation changes the answer to ambiguous. The domain walk is finite and its closure is not an exhaustive account of a person's occupations or types.
2. A forward question has four linked in-domain candidates: the first three have value A, the fourth has no value. The kernel answers A; adding B to the fourth makes it decline. `pool_agrees` explicitly ignores empty value lists. The statement `snapshot_complete_wrt S p c` in `Relation_Reader.thy` equates fetched nonblank values to a supplied snapshot. It does not prove that the snapshot includes all facts or that a value-less candidate is not the intended subject.
3. The appliance source's inverse path queries only `qids[0]`. The test supplies two equally ranked linked targets, each with a distinct subject. The function queries only the first and answers its subject. Dominance, top-three selection, and the six-candidate linker cap are also not proofs that the discarded senses are impossible. The test controls recognition and fetch, and therefore does not claim that a particular natural-language question currently fails end to end.
4. Actual front door invocation using `var/relations/bin/decide` and the configured relation snapshot: `Which actor is married to Yoko Ono?` returns `answered`, `John Lennon`, with the receipt “stored wives (P26)”. A spouse edge without temporal qualifiers supports a stored relation, not the present-tense claim. `finish` silences past tense for time-varying properties, but accepts present tense. The direct source-relative observation does not establish the relationship's real-world dates or a panel result.

## Why the proofs do not close the gap

`inverse_answer_snapshot_identity` states that, **assuming** the supplied subjects exactly cover all source edges to supplied target IDs and `E` agrees with `identity_matches` for each subject, the eligible source set is the singleton returned. The second premise is the open question: negative matches in a partial knowledge graph are not necessarily negative real-world facts. It also ranges over supplied target IDs, not all intended senses. `queried_forward_answer` establishes an in-scope stored row, not an exhaustive world interpretation. These are useful source-relative theorems; neither proves the stronger natural-language conclusion without explicit completeness and interpretation premises.

## Repair for integration

- Represent requested-kind eligibility as positive, negative, or unknown. Count a negative only where explicit evidence and an appropriate exclusivity/completeness premise justify it. Unknown subjects that could satisfy the requested kind prevent a uniqueness answer; surface a careful refusal or ambiguity. A complete SQLite query is not by itself that premise. Domain exclusions such as absent P576 must also avoid equating “no stored dissolution date” with “current.”
- For forward questions, either retain and resolve every plausible linked sense or refuse when an in-domain candidate lacks a value. This repairs the four-candidate counterexample but still depends on explicit candidate and domain-coverage premises; it does not resolve omitted names or missing type facts.
- For inverse source readers, collect subjects across every credible target identity; require bounded fetches to detect truncation and refuse on overflow. Preserve target identity in the evidence and refuse if the question cannot distinguish targets. A local `continue` or silent return alone is insufficient if later routes can guess, so the dispatch consumer must retain a refusal.
- Require temporal coverage and an explicit as-of interpretation for “is/current”; alternatively phrase the result only as a stored historical relation and do not present it as a current answer. A list of time-variant properties or a past-tense guard alone cannot establish the required interval.

These are repair conditions, not an integration-ready patch: they need a shared policy for unknowns, source completeness and downstream refusal before changing consumers. A simple “missing means false” patch would restate the bug. The tests assert the current behavior as a regression witness; after a repair their expected results should be changed to refusal or clarification.

### Next kernel change and theorem to prove

Add an explicit three-valued requested-kind predicate (`Yes`, `No`, `Unknown`) and a three-valued target binding/coverage input to the identity kernel. Choose a subject only when target coverage is established, every source subject is covered, exactly one subject is `Yes`, every other subject is `No`, and all source/ontology coverage premises needed for those classifications hold. `Unknown` must block unique choice rather than be filtered out. A useful theorem statement is:

> If `decide_identity` answers subject `s`, the supplied target IDs equal the intended target set, the fetched subject IDs equal all snapshot subjects related to those targets, and each `Yes`/`No` classification agrees with the intended eligibility predicate (unknown classifications are permitted but prevent an answer), then `{u. eligible u ∧ (∃t in targets. (u,p,t) in snapshot)} = {s}`.

This is a proposed statement, not a proved theorem. It is source-relative: a world-level claim additionally needs a premise that the snapshot covers the relevant real-world relations, along with any identity and temporal premises. No Isabelle build was run.
