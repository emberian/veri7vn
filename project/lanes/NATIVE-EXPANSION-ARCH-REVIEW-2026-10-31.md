## Phase-2 work/memory identity overlay review

Reviewed the minimal `oracle-execution/src/lib.rs` overlay at SHA256 `996bfa88b8fe20cf74c7d7c4e9e518414f9e049aa2875644bd91141cf98e4943`, against the sealed first-wave source. **No blocking correctness finding.** No build, test or performance measurement was run by this reviewer; the first-wave checkpoint remains unchanged.

Previously, every `restricted_memory` call introduced another `ExecutionInner` with a redundant `u64::MAX` allowance and the same deadline/cancellation. All checks and charges then traversed those artificial work ancestors. The overlay stores the work `Arc<ExecutionInner>` and `MemoryBudget` separately in `ExecutionContext`. Memory restriction now retains exactly the same work Arc and creates only the intended memory child. Genuine `restricted(fuel, timeout)` still creates a work child, points to the actual parent work Arc, preserves the minimum absolute deadline, and shares the current memory ledger.

Moving `check`/`spend` to `ExecutionInner` preserves their control flow and atomics: ancestor checks precede local checks, cancellation/deadline/sticky-exhaustion order is unchanged, parent fuel is charged before local fuel, and a failed local charge may still conservatively consume parent allowance without refund. Memory-only views neither mint fuel nor clear exhaustion. Cancellation registration still delegates to the same shared cancellation object. Dropping work contexts cannot prematurely refund a live allocation: reservations own the memory scope ancestry independently. Genuine work descendants retain their current memory scope through the context's separate ledger field.

Inspected three new regression sources: `repeated_memory_restrictions_preserve_exact_work_identity` asserts pointer identity and absence of artificial work parents through 64 memory restrictions, then exact shared fuel use; `memory_limits_survive_genuine_work_restriction_and_cancellation` checks memory ancestry, real work-parent identity, conservative failed local charge and cancellation without early release; `memory_view_of_work_child_cannot_bypass_local_fuel_or_deadline` checks sticky local exhaustion, tighter memory ancestry, reservation survival after views drop, and genuine local deadline expiry. Existing shared-fuel concurrency and cancellation tests still target unchanged atomic logic.

This removes a demonstrated structural source of redundant checkpoint traversal. It does not by itself establish that the structure caused the observed graph slowdown, quantify any recovery, or guarantee faster cloning: context clones now separately retain the memory ledger. The narrow immutable-overlay measurement and central execution remain the required evidence for performance and integration claims.
