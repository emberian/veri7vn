The operation answers finite minimum walk weight, unreachable, or unbounded below
for exact directed i64 multigraphs. Edge IDs are input positions. Checked i128
arithmetic supports totals beyond JavaScript integers; JSON values are decimal
strings. Negative cycles matter only when reachable from the source and able to
reach the target. Nonnegative corridors use an integer binary heap; signed ones
use Bellman-Ford. Standard petgraph shortest-path routines do not expose the
required exact three-outcome certificate contract, so the candidate uses compact
edge-ID adjacency directly rather than wrapping a second graph allocation.

Independent checks establish these statements over the complete supplied graph:

- A finite path attains the declared distance. Labels cover exactly the
  source/target corridor, label(source)=0, and label(v)<=label(u)+weight(u,v)
  on every corridor edge. Telescoping bounds every source/target walk below by
  label(target), so the attaining path is minimal.
- An unreachable witness contains the source, excludes the target, and is
  closed under every supplied outgoing edge. Thus no source/target walk exists.
- An unbounded witness contains a source prefix, a nonempty closed negative
  cycle, and a target suffix at that same anchor. Repetition makes walk weights
  arbitrarily negative.

These are Rust checks, not Isabelle theorem statements. Missing graph edges are
absent only within the caller's supplied graph; there is no external-world
completeness claim. Bounds on vertices, edges, work and elapsed milliseconds,
plus cooperative AtomicBool cancellation, apply to search and check together.
Public standalone checking has its own identical budget. This is cooperative
resource control, not process containment.
