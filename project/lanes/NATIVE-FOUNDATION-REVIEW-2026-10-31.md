## Late numeric boundary finding

The typed author identified a real scalar-conversion discrepancy missed by the initial numeric inspection. With `arbitrary_precision` but without `float_roundtrip`, `Number::deserialize_f64` uses Rust string parsing while serde_json's wire `f64_from_parts` first rounds an integer significand and then scales it as a float. Those are not generally equal. The installed serde_json 1.0.154 source itself documents `51.248178375505404` in `tests/test.rs::test_roundtrip_f64`: the old deserializer returns `51.24817837550541`. A bounded Python calculation of that exact source formula confirmed bits `0x40499fc44f1b2f61`, versus correctly rounded decimal bits `0x40499fc44f1b2f60`. This calculation was not a Rust build or project test.

Recommended correction: enable workspace serde_json `float_roundtrip` while retaining `arbitrary_precision`, and add central bit-level assertions for typed and wire boundaries against independently fixed expected values. This intentionally corrects the old wire rounding rather than preserving inferior rounding with domain-specific reparsing. The existing `&Value` numeric deserializer observation was accurate but insufficient to establish equivalence to RawValue parsing. Root was notified and commit paused for correction/validation. This addendum supersedes any earlier implication of complete numeric equivalence; closure/budget review findings are unchanged.
