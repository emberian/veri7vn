# Native exact segment chains and one nested fragment pass

Owner: native_segment_reader. Consumer: `Image::read_whole` and Runtime's shared
language evaluator through `reader.rs` → `composition.rs` → `segments.rs`.

## What is authored

The native reader can build entity chains from exact learned segment rows and
put a pre-nested chain into one exact learned nested fragment. It keeps direct
whole-question and exact fragment readings, so a new interpretation cannot win
by hiding an older interpretation. Every successful alternative still reaches
the existing answer-form veto and final answer-agreement rule. Learned support
admits rows under the existing trust policy; it never elects an answer.

## Source behavior preserved

A segment spans at most 12 words. A chain contains 2–4 segments and at most one
source segment. The source goes first even when its words come after a filter.
Without a source, execution starts with `FindAll`. Concept-filter units precede
other filter units, preserving surface order within each group and preserving
qualifiers attached to each unit. Assembly gives each step its preceding step as
its dependency.

The ordinary exact fragment and nested fragment bounds remain 30 words. A chain
of four 12-word segments may span 48 words, so outer holes admit that source
family's larger span. This changes a language-family bound, not host budgets.
Nested fragment templates receive only base exact fragments or segment chains,
never another nested result. The native code does not invent recursive nesting.

Indexed prefixes prune impossible words/slots. Only a complete learned outer
question demands region work, and only a complete learned nested wording demands
its child regions. Unit lookups and base regions are memoized across those
questions. A mutable DFS path replaces copied frontier states. The host combination cap counts admitted runnable/nonempty base region/program nodes together
with their child-region/program witnesses, then complete resolved outer
interpretations. Repeated equivalent unit paths share an endpoint/role/program
node. Unresolved outer holes, nested hole splits and individual units remain
bounded by fuel, bytes and row/match envelopes; they do not spend the resolved
interpretation cap. Genuinely different resolved programs or child witnesses
still spend that same cap. Host binding, program, materialization and
request-budget exhaustion return an error, never a truncated answer set. The source's silently truncated frontiers are not copied.

Before executing anything, composition requires every hole in an outer program
to have complete syntax. It first validates the union of selected pre-nested child programs, then
validates admitted parent programs once per distinct program with the caller's
existing shared `LanguageWorkspace`. Child witnesses are retained even when a
parent skeleton omits its template's `@X` splice. Nested syntax is retained as a delayed skeleton plus shared child-choice sets.
The complete outer syntax establishes demand; the shared semantic evaluator
checks the full consumed base union before any nested products are formed.
An empty child prevents that parent from being formed or running; an unsupported child remains an error even when an empty
child alternative produces the same parent program. Deduplication includes child
admission witnesses until those checks complete.
Unconsumed unsupported regions cannot poison an answer; consumed unsupported
operations remain explicit errors, including when an empty sibling could
otherwise erase them. Every entity stage, including a dead branch, must be
nonempty before a fragment is usable. A terminal outer `Count` cannot turn an
empty fragment into a zero answer.

## Scope and evidence

This remains an untrusted language recognizer. Missing source rows do not prove
absence or completeness. Exact matches are covered; content-key and strip-key
fallback, analogy, clause patches, date wrappers and deeper nesting remain
outside this coverage. The public coverage declaration includes
`exact_segment_and_single_nested_v1`; no full Reader7 claim is made.

The contracts cover source/filter reordering, all segment alternatives, exact
and segment children of nested templates, mixed whole/exact/segment/nested answer
disagreement, the one-pass boundary, source-free `FindAll`, two-source rejection,
qualifier attachment, stable concept-first order, four versus five units, the
48-word chain bound, empty intermediate stages, unused and consumed unsupported
regions, form veto, resource exhaustion, cancellation, recovery and worker lease
cleanup. Five additional contracts cover omitted `@X` with empty, unsupported
and valid children, empty/unsupported alternatives yielding identical parent
programs, and repeated child-program admission cache reuse. The independent KB has two York residents, one birth there and one
shared employer. Its nested employer count is 1, while its resident count is 2.
One malformed learned-row adversary deliberately attempts to resurrect an empty
child through an unrelated later branch.
