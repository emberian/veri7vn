# NDIST — native appliance distribution

Owner: Codex distribution lane. Consumer: the central integrator and operators
running the existing private native service outside a source checkout.

## Scope and changes

New files only:

- `tools/appliance/package_native.py`: explicit twelve-file Python closure,
  exact operator-supplied extension digest, relocatable isolated launcher,
  complete payload hash manifest, external operator example, atomic exclusive
  directory publication and optional deterministic archive.
- `tests/appliance/test_package_native.py`: manufactured integrity, collision,
  path, import audit, relocation and archive contracts; an opt-in combined
  extension journey through packaged CLI discovery, bio/statistics/supplied
  graph calls and durable reader exact retry after restart.
- `native/docs/DISTRIBUTION.md`: manufacture, receiving-host requirements,
  identity boundaries, external sidecars and qualification commands.
- This report.

No existing runtime, worker, pool, service, source, main README or upstream path
is edited by this lane. No new theorem is introduced; no theorem statement is
claimed. No specialist-panel numbers are available for this packaging lane.

## What it does and what it establishes

Inputs are an explicit extension path and lowercase SHA-256, an absent output
path and an explicit requested profile list. It copies only that extension and
the reviewed fixed service import closure. It never copies an interpreter,
whole repository, image, corpus, credential, private config, journal or cache.
The dynamic runtime sibling loader is included. Dormant Engine-only imports in
the shared transport/operations files are enumerated; the native entrypoint
constructs `Operations(None)` and never invokes those paths.

The component adapter is `native_runtime_adapter.py`; the appliance host helper
retains `native_runtime.py`. The explicit package list follows that production
rename, avoiding the former duplicate basename when component paths are added
before appliance paths by another embedding host.

The generated launcher locates payload from its own path, enters Python
`-I -B -S` isolation, verifies every payload's digest/size and the complete file
set, resolves only this bundle's extension and passes the operator's external
runtime sidecars through the existing service parser. It does not need the
working directory, `PYTHONPATH`, Oracle7 or Mini. Requested profiles remain
unqualified in its manifest; service startup and central actual-artifact tests
check real exports/catalogs. The manifest records declared code version and
source hashes, with no inference that the artifact came from that source.
Extension API version is observed in actual qualification.

Directories publish with atomic no-replace rename on Linux/macOS. Archives have
fixed gzip/tar metadata and exclusive publication. The archive and directory are
two destinations, not one transaction; archive publication may survive a later
directory collision. Paths reject traversal and symlink components. Local hashes
are unsigned integrity metadata, not interpreter/build attestation. CPython
3.12+, matching OS/architecture/ABI and linked system libraries remain host
requirements; no network installation or root deployment occurs.

## Checks and actual result

This lane was explicitly assigned implementation with central-only execution.
It ran no builds or test commands. All tests are authored and await the central
integrator's scoped execution. There is no passing or performance claim yet.

Proposed central commands:

```sh
python3 -B -m unittest discover -s tests/appliance -p test_package_native.py -v
ORACLE_NATIVE_TEST_EXTENSION=/operator/combined/oracle_native.so \
  python3 -B -m unittest discover -s tests/appliance -p test_package_native.py -v
```

The actual case needs all six profiles and the existing tiny-image fixture
helper in `test_native_runtime.py`. It packages outside the source tree, moves
the directory, uses an unrelated working directory and retains external state
through service restart. The central receipt should record actual extension
SHA-256/API version, packaged manifest digest, verified actual profile exports
and exact result counts; this report must be updated with those results.

## Remaining

Central qualification, remediation of any failures, main documentation link and
commit are owned by root. No automatic publication, dataset transmission or
remote installation is performed. Receiving-host dynamic-library qualification
is still needed for every target OS/architecture; a local bundle is not a
cross-platform artifact or signed release. Existing service security, runtime
admission, retention and cancellation contracts remain the governing limits.
