## Decisions

An explicit supplied-snapshot Count mode is reasonable. Its answer counts stored
matches in the supplied records; it does not establish a complete source domain
or world absence. The default policy stays unchanged. The mode must appear in
reply provenance and must not be inferred from learned grammar, a Count/Exists
hydration request, or missing attribute rows.

Under this mode only actual terminal Count permits empty output and empty stages
in its dependency ancestry. Empty dead stages still refuse. A syntactically
consumed child omitted from its parent's program keeps an independent strict
nonempty obligation. Unsupported candidate interpretations remain obligations;
this change must not prune them to manufacture agreement.

The policy author's design stages executable fragment candidates with permissive
live ancestry, separately caches strict checks, checks omitted children at each
parent, and reapplies the actual outer obligations to the complete program.
This avoids a context-free bool declaring an empty fragment universally viable.
Fragment-dead stages cannot become live later because parents consume only the
fragment output. Integrated source review approves the implementation: viability
keys include the strict/permissive flag, both immediate omission sites check
strict obligations, and final query admission reapplies each occurrence's policy
even on cache hits. ReaderOptions and ReaderResult expose the supplied scope.
Policy contract-case execution remains required.
Final policy test-source review approves the seven public language cases in
`reader_count_contract.rs`: explicit composed zero, live union versus dead empty,
non-Count strictness, same child live/omitted, missing attributes without source
closure, nested omission, and unsupported sibling veto.
