## Concrete change

The inverse reader previously asked only for subjects of the most popular linked
target. John Williams, John Adams, John Smith, William Morris and Elizabeth Taylor
all have distinct linked identities with different supplied spouse subjects.
Merely checking each specialist's domain also misses alternatives: Teio is human
and a stored spouse of one John Adams, but has no occupation rows that place her
in the 91 person-reader domains. Choosing Abigail Adams after discarding Teio is
not justified by a general person request.

The new finite model fetches a union of subjects for every supplied target ID,
retains exact entity IDs in relation rows, and checks the requested-kind pool
before any specialist domain can authorize an answer. It requires complete row
and class flags for every fetched subject, distinct subject IDs and an actual
raw edge to a supplied target. Overflow of the 256-distinct-subject union refuses.
A missing label does not erase an alternative identity. The flags still come
from untrusted fetching; they do not prove completeness.

Exactly one eligible subject may answer after specialist ownership and ordinary
restate/time/pronoun guards. Multiple linked targets may share that one subject;
no popularity choice is then necessary. Different eligible subject IDs produce
a source-relative clarification listing alternatives. Equal display labels do
not merge IDs. The source's absence of a dissolution row is an explicit exclusion
for its country model, not proof of present-day political status. Spouse replies
identify stored assertions, not current marital status.

The untrusted reference confirms global ambiguity for all five sampled homonyms,
including John Adams, while preserving Marie Curie → Pierre Curie. Yoko Ono has
multiple human spouse subjects in this store; her actor-qualified request still
has John Lennon as the unique matching actor. No reference result is counted as
an extracted-kernel check.

## Conversation boundary

The adapter now prepares `provenance.conversation` with property, direction and
slot surface. A query entity is emitted only when the native domain-filtered
forward candidate IDs (or all inverse target IDs) form a singleton. An inverse
answer entity is its selected subject ID; a forward answer entity requires every
raw entity/literal property row to name one identical entity ID. Unlabelled IDs
remain alternatives; rendering cannot erase them to create conversational identity. A repeated display
label cannot create an identity. Person classification uses supplied source
classes/closures; a limited explicit set of nonperson reader domains supports
thing classification. The finite source-class map also supports typed answer
entities (for example Vienna as a city). Canonical singular `entity_domain` is
optional; conflicting classes stay unknown and an explicit human class takes
precedence. Everything else stays unknown.

The optional `bound_query_entity` carries `{qid,surface}` from the dispatcher's
own stored accepted reply. Runtime must never forward user-supplied JSON as that
context. The adapter requires the surface to equal both the current stored label
and every rewritten recognized slot, then fetches exactly that supplied ID.
Mismatch is a decisive refusal. The binding is declared supplied context; it is
not a proof that the previous conversational referent was correct. The dispatcher
owns history, admission and selection of this context.
