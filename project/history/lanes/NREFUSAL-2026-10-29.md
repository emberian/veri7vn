## Behavior and boundary

Previously every native input refusal retired its process. This change keeps
a resident process only when a bio/statistics call ends at an explicitly typed
invalid-input or resource-limit boundary. It preserves the HTTP reply's
`status=withheld`, `reason=native_request_refused` and
`authority=computation_only`. Statistical fits without inference remain
answered fits with their explicit classification and unavailable reasons.

`oracle_native.NativeRequestError` is an optional subclass of `ValueError`.
Its arguments are exactly `(code, message)`. The bio and statistics bindings
map only their native `Error::Invalid` and `Error::Limit` variants to it, with
codes `invalid_input` and `resource_limit`. Numerical failures, checker
disagreement, cancellation and JSON errors retain their ordinary error
boundary. In particular, the shared JSON error variant covers both parsing
and serialization, so it does not receive a reuse exemption.

The fixed worker policy recognizes the exact exported class, not subclasses,
for the host-admitted `bio` and `statistics` profiles and `call` action only.
Known error codes and a valid UTF-8 message of at most 512 bytes are required.
Unknown codes, malformed metadata, oversized messages, ordinary ValueError and
catalog failures follow the retiring path. An older extension without the
typed export continues to work under that conservative behavior.

The new internal response is exactly:

```json
{"id": 1, "outcome": "request_refused", "error": "native_refused", "code": "invalid_input", "detail": "invalid input: supplied data"}
```

The parent validates the exact fields, request ID, fixed admitted profile,
action, code and message bound independently. Only that validated response
marks the slot reusable before raising the existing `NativePoolError` with
`code=native_refused`. It also exposes `request_code` to trusted pool callers.
The existing finally path still releases the tenant lease and busy slot.
Every unexpected outcome, fault, untyped refusal, malformed frame, timeout or
cancellation retains retirement and owned-process cleanup. Uncertain cleanup
continues to consume a poisoned slot. No request-defined reuse flag, exception
class, extension path or authority is accepted.

One pool and immutable artifact snapshot continue to serve both profiles and
multiple host-assigned tenants. Global capacity, immediate busy responses,
no-queue behavior, process ownership, CPU lifetime limits, memory limits and
hard-deadline supervision are unchanged. Keeping a process resident does not
reset its cumulative CPU allowance. Additional providers would need an
explicit native error mapping and fixed host-policy review; their catalog
cannot opt into this boundary.
