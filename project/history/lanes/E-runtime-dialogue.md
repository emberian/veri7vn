# Final-turn context and connected runtime stages

This packet makes context useful in the actual dispatcher: relation pronouns,
subject and predicate ellipsis, exact numeric result conversion/cost, solved
variable powers, and literal recall of final answers. It also connects the
checked code generator and the document anchor front door. There is **no new
specialist-panel score** and no 237-turn conversation completion claim.

Personally inspected the actual upstream `chat_context_v2.py`,
`organ_dialogue_v1.py`, conversation scout source/report, and cv190b7e04/ad7f4cab
surrounding exchanges. The scout's 236/237 scored recorded head replies; its own
policy agreed on 161/237 decisions. Rendered-text linking and a nominal
single-dispatch identity did not establish correct reference grounding or real
probe purity. This implementation uses final producer receipts and separates
route evaluation from effects.

## What runs

Each dispatcher connection has a separate ledger, partitioned by session. A
final event records the original question, the standalone question actually
used, and the final post-guard/post-commit reply. Evaluation appends nothing and
cannot commit warehouse effects. Only one selected guarded evaluation can
reach the private committing child, once; failures are never retried. A
substantive refusal or an answer without supported context clears reusable
ground. Recall quotes final text and its source provenance without promoting it
to a new truth claim.

Query and answer entities remain distinct. Only accepted structured relation
IDs and source-derived types ground them. Unknown types can compete with a
known person; an unknown query entity can compete with a known answer thing.
Ordinary thing references prefer the known query thing, while “that thing”
uses the answer thing. Country/city references additionally require the matching
supplied subtype. Exact Fusion values carry their unit; affine solved variables
require a consistent independently replayed packet bound to the question.
Python performs no follow-up arithmetic.

Complete finite follow-ups select their question before invoking any route.
Missing or ambiguous references clarify. A contextual refusal stays terminal;
there is no retry of a different literal interpretation. Explicit `It`, quoted
titles, and incidental pronouns inside standalone questions retain the raw
reading. This repairs the concrete Leaves of Grass → “Who wrote it?” collision
without overwriting a refusal already issued by a kernel. Incoming JSON cannot
provide entity bindings. An internal binding must originate in the stored
receipt and match the relation reader's exact rewritten slot.

A successfully committed warehouse final receipt can retain an opaque native
context owner, without inventing a global entity ID. Finite inventory/location
follow-ups delegate to that exact CLI-pinned specialist in the same session.
A preview, failed commit, other pin/session, or intervening unrecognized turn
cannot authorize that delegation.

Code requests reach their own reader before numeric specialists in both stage
orders. Otherwise “write a function converting kilograms to grams” was wrongly
answered with a scalar weight. Code answers require `code_program`, the exact
request text, and a consistent independently checked program/examples/source
packet. Captured code refusals stop routing. Ordinary numerical questions fall
through. Document now invokes `tools/document/frontdoor.py` with both explicit
legacy and anchor binaries; missing configured programs fail startup.

## Limits and changed paths

Unknown source classifications can require clarification even when a human
would infer a type; Newton→Woolsthorpe→he is such a case, whereas Huygens→The
Hague has supplied types. General unit-result grounding and arbitrary discourse
are not implemented. Wh and ordinary MJ/GJ/MWh conversion gaps were reported to
the Quantity owner; dialogue does not invent conversion arithmetic. Memory is
in-process and lasts for the connection; it is not persistent chat storage.

Owned changes: `src/extract/converse/`, `tools/dialogue/`,
`tools/dispatch/{dispatch.py,README.md,test_dialogue.py,test_code.py}`, and this
report. Parent owns the dialogue/code registry and shared evidence validator;
producer owners retain Math, Relations, Stores, CodeOrgan, and Document source.
The consumer is the normal JSONL dispatcher. `--no-dialogue` and `--no-code`
explicitly disable their stages. No upstream file was modified and no full-head
sweep was run.
