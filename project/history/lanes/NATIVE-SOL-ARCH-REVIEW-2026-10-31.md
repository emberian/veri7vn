## Findings resolved in source

**P2 — Reader selection escapes its reservation.** `reader::evaluate_inner` clones the agreed `ReaderShared<Selection>` into a plain `Selection` just before return. The new allocation is uncharged while both copies exist, and its original shared reservation disappears when the local workspace drops. `Runtime::execute_inner` then retains that selection through `SessionSelection` replacement, encoding and transactional state processing. This is an ownership gap in an explicitly instrumented payload, not a claim that all process memory must be measured. The reader author confirmed and repaired the return/state boundary, as detailed below. The decisive regression must keep the returned selection alive after dropping reader evidence/workspaces, show its reservation remains live, and show final release only when the selection consumer finishes. A duplicate-allocation variant should refuse a cap insufficient for both simultaneously live copies, or avoid the copy entirely.

**P2 — Composition output reservation ends before its payload.** `composition::match_composed` returns `Vec<MatchedProgram>` while its local `segments::Ledger`, including `Owner::Output`, drops. `reader::evaluate_inner` extends a preexisting matched vector with that result, and only afterward reserves a new conservative envelope. This temporarily frees credit for live instrumented output and also leaves the preexisting whole matcher vector uncharged during composition. The reader author repaired the handoff, as detailed below. The decisive regression retains returned composed candidates while another charge attempts to consume their allowance: it must refuse until candidates are dropped. Reader combination must avoid a gap or a double charge when transferring ownership.

**Measurement hook retention.** `reader::probe::enable` originally switched on a permanent global `Vec<Record>` with neither a bound nor disable operation. This does not affect normal disabled production execution, but repeated measured reads could grow bookkeeping independently of request budgets and distort long-running memory measurements. The author added a bound and disable operation, as detailed below. A bounded-record overflow/disable regression is appropriate.

## Host lifetime, readiness and uncertainty

The frozen `InvocationWorkers` design has direct handoff to fixed slots, immediate refusal when all slots own work, and no waiting queue or fairness guarantee. A slot remains occupied through execution and closure destruction. `Service::invoke` captures provider Arcs, context and admission permit; it does not capture `Service` or the pool supervisor. Worker threads own shared slot state, not join handles. This removes the Service/worker self-join ownership risk. Shutdown serializes joins, closes admission to handoff, then drains accepted jobs; partial startup failure drops and joins earlier workers. No lock cycle was found in these paths.

Timeout cancels the request without releasing a running worker's global/per-tenant permit. Panic unwinds the closure, releases its permit, disconnects the reply and leaves the worker reusable. Stateful timeout/disconnection retain uncertainty and exact-retry semantics. A handoff refusal returns retryable 429 with no possible state change because execution was never accepted. There can be a small interval after sending a reply and before marking its slot idle in which another caller sees 429; this is consistent with immediate refusal and does not claim fairness.

`http::listener_ready` now uses OS readiness (`poll`), replacing the old 20 ms accept sleep. The 100 ms timeout only bounds idle observation of the stop flag; arriving connections wake readiness immediately. Interrupted waits/accepts retry; permanent errors leave the loop and drain. `ConnectionGuard` accounts accepted handlers across normal return, panic and failed thread spawn. `Connections::drain` waits on its predicate under the same mutex used by drop notifications. The serving thread holds its own Service Arc while draining. No self-join or missed-notification path was found. Actual latency improvement still requires the central measurement, not this source argument.

## Final repair pass

Selection now returns as `ReaderShared<Selection>`. `ReaderShared::into_owned` transfers a uniquely owned payload and its existing reservation without copying; if another owner exists, it reserves for the real second allocation before cloning. Runtime places the moved selection and guard in `RetainedSessionEnvelope`, whose payload precedes its reservation in field drop order. The serialized state receives a separate preallocation reservation, held through the transaction, and the source envelope drops explicitly after encoding. This closes the escaping live selection gap, including early-return cleanup. The graph branch acquires its own selection reservation to share the same runtime seam.

`ComposedMatches` now owns the returned programs and their reservation. `Ledger::into_output_memory` shrinks only away from chart/arena owners that have already dropped; it transfers the remaining output charge without a release/reacquire interval. Output charges use the retained-representation envelope rather than raw encoded size. Reader reserves the whole matcher output before beginning composition and consumes the two batches by chaining under their respective guards, avoiding the old append-and-recharge gap. The public Rust return type of `match_composed` changes from a vector to an immutable slice-dereferencing wrapper; public JSON output remains unchanged.

Reader measurement records now cap retention at 1,024 entries. `disable` clears records, and `record` rechecks enabled state under the lock so a pre-disable caller cannot repopulate the buffer after clearing. The retained vector capacity is bounded; this is measurement bookkeeping outside request accounting.
