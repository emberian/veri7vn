The adapter describes three known native computations: a minimum spanning
forest of a caller's graph, exact dimensionless polynomial optimization, and
polynomial optimization with caller-supplied SI dimensions. It preserves
native result fields, including decimal-string graph weight totals, the
reported independent Rust checks, and dimensional selection fallback. It does
not itself prove the native result, infer units from names, convert scales or
affine quantities, or establish a physical law.

Named phase timings (`build_us`/`search_us`/`check_us` for graphs and
`normalize_us`/`search_us`/`check_us` for both polynomial operations) are optional
u128 JSON integers. When supplied they are preserved exactly, including values
above u64. Older replies without timings remain valid; required semantic
fields remain required and unknown result fields remain rejected.

The ordinary `ReasoningOperations(runtime, workspace)` constructor describes
the operations as unavailable. Its paths are never opened. Activation needs a
host-selected `oracle_native` module object, the literal operator flag
`enabled=True`, and a nonempty host-supplied runtime identity. There is no
module search/import, environment activation, caller path, per-tenant worker,
or request field that can enable the provider. The identity is explicitly a
host assertion, not a checked artifact identity or admission attestation.

Live resource ceilings come from the bound native catalog's `limits`; Python
does not mirror the native default counts. Dimensional exponent bounds come
from the operation's `max_exponent`, with the known SI axis order
checked against `dimension_order`. Missing features/backends/catalogs stay
unavailable. Unknown catalog operation IDs are ignored; absent known IDs or an
unsupported dimensional schema stay unavailable individually. Native search
limits remain cooperative. The adapter additionally bounds native JSON replies
at 262144 bytes and declares that cap.

Malformed structured requests raise `ValueError` before a native call, matching
the appliance provider interface. Native `ValueError` failures after dispatch
are withheld results with bounded details, since they may describe resource or
independent-check failures after computation. Unexpected execution errors and
malformed native replies also withhold. No reply is changed into a proof or a
Mini permission.

## Consumer and exact host hooks

The intended consumer is `tools/appliance/operations.py`'s fixed extension
provider loop. This lane did not edit that file or package manifests.

For discoverability alone, root can add this fixed tuple to `_extensions()`
and include the adapter at the packaged filename through the existing bundle
inventory:

```python
("reasoning_operations.py", "tools/oracle_components/reasoning.py", "ReasoningOperations")
```

That two-path constructor remains disabled. The current Python Oracle appliance
has no selected native runtime to bind, so exposing declarations alone does not
make this a completed native host journey.

An actual native host can construct its provider once on its existing runtime
thread, using the factory exported by the same fixed adapter file:

```python
provider = create_reasoning_operations(
    config.runtime, config.workspace,
    native_module=host_selected_oracle_native,
    runtime_identity=host_native_runtime.identity,
    enabled=operator_settings.experimental_reasoning is True,
    backend="oracle_native",
)
```

The factory's module, identity and enabled flag come from host configuration,
never operation arguments. Register `provider.catalog()` through the existing
descriptor/add loop, and bind the existing invocation wrapper to
`provider.invoke(operation_id, arguments)`. Its `ValueError` handling already
maps pre-call validation to `invalid_arguments`. The host still owns loading,
deployment provenance, access policy, transport budgets and process limits.
There is no automatic release registration or Mini capability hook here.
