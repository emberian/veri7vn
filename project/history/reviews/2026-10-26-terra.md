## Appliance service review

The service documents its single-workspace trusted-host boundary and that its SQLite journal is not a transaction with the engine. The review did not run a whole Oracle Engine or measure panels.

### P2: a slow local connection can exhaust the HTTP slots

At review time, `tools/appliance/serve.py` used a five-second socket timeout, which bounds inactivity of each socket read rather than total header/body lifetime. A peer that sends a byte before each timeout can occupy a slot indefinitely; enough such peers starve health and queries. Because handler threads are joined on shutdown, a slow ingress can also delay shutdown. **Measured** using the actual server with one slot and a shortened 0.12-second timeout: a header drip every 0.07 seconds occupied the slot for 0.49 seconds and a concurrent health connection was reset. This is an availability issue from local clients within the documented trust boundary, not a claim that loopback is authenticated. Use an absolute monotonic ingress deadline and close outstanding ingress sockets on shutdown.

### P2: workspace may contain the source or data root

The CLI checks whether workspace is within the runtime or data root but, at review time, did not check the reverse. Workspace `/srv/o`, runtime `/srv/o/code`, data `/srv/o/root` passed the check. Since the worker changes cwd to the workspace, an upstream relative write under `root/` can then land in the data root, contrary to the intended isolation. **Source-confirmed**, without writing to those locations. Reject overlaps in both directions using resolved paths; the host must still mount the runtime and data read-only as documented.

Both findings were sent to the appliance implementation lane, which reported it was adding absolute ingress deadlines, shutdown handling, bidirectional path checks and focused tests. These are pending changes, not yet independently verified here.
