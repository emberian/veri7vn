- Useful solver/checker composition: grow symbolic, graph and scientific
  operations around typed inputs and independently checkable results. Reuse the
  extracted kernels where their statements cover the result; extend assurance
  selectively rather than recoding them just to use Rust everywhere.
- Broader statistical and biological specialists: the current native surfaces
  are bounded linear regression and pairwise DNA alignment. Start a substantive
  statistical modeling consumer and retain bioinformatics as a parallel growth
  avenue. Score affected shipped panels and independent cases separately.
- Explicit conversation state: migrate hot state owners into the existing typed
  session record, including referents, quantities and pending conversions. This
  enables cross-provider follow-ups and cheaper tenant switching; worker
  isolation alone does not provide either.
- Learned computation/readouts: evaluate useful computations or typed candidate
  programs from learned representations against independent cases. Preserve
  empirical status where no checker establishes correctness; do not discard a
  useful learned computation merely because it is not yet symbolically derived.

These are proposed next batches, not claims that implementation has started.

## Source orientation: ownership and useful connections

The following records the 30 October baseline. The 31 October recovery, ownership
and worker-package repairs above supersede those findings where noted.

The 30 October source reading traced both host entry points, the Engine worker
lifecycle, the older Python pools, core transactions and representative domain
implementations. These are source findings, not new execution receipts.

- The [core image](../native/oracle-core/src/image.rs) owns a bounded pool of
  read-only SQLite connections, private temporary tables and per-tenant execution
  admission. Public data is shared; per-worker caches and request scratch still
  cost memory. [Core turns](../native/oracle-core/src/runtime.rs) look up completed
  retries before acquiring an execution slot, evaluate against a session revision,
  then atomically commit the new session and reply. Preserve this boundary.
- The [host query path](../native/oracle-host/src/service.rs) has a separate
  journal and Engine-worker conversation binding. The baseline bound after
  execution and could forget a changed request on storage failure. The current
  implementation reserves conversation ownership and persists dispatch before
  Python execution, retains uncertain outcomes, and replays completed requests
  before acquiring execution capacity. Pure core evaluation can roll back; an
  opaque Python turn cannot. Keep that distinction in the public result.
- Native `/query` calls `read_whole`, without a conversation, whereas native
  stateful `/invoke` uses core sessions. Engine fallback has its own memory.
  Routing alone therefore does not transfer context between providers. Define
  which structured context each provider consumes and returns before connecting
  follow-up questions. Session-name hashing alone does not establish isolation
  of the Engine's other mutable state; that state still needs an ownership audit.
- [Pure calls](../native/oracle-host/src/pure.rs) run inside the host. An HTTP
  timeout retains the execution permit until the call ends, but cannot kill the
  thread. Reasoning and incremental calls do not receive the host cancel flag;
  they use their own budgets. Statistics explicitly identifies uninterruptible
  SVD work. Select containment per provider and propagate one request deadline.
- Most new domain providers are structured operations, not question routes.
  [The graph organ](../src/extract/graph-native/oracle7-organ/organ_algorithms_native.py)
  demonstrates the missing connection: a conservative recognizer constructs a
  typed request and checks the returned answer against it. Keep that recognizer
  untrusted and retain useful direct operations beyond its language coverage.

The strongest shared performance idea is demanded computation. Scalar query
demands avoid result materialization; composition delays fragment execution;
rooted incremental analysis bounds retained pairs by the requested roots. The
incremental API currently builds a dataflow for a supplied batch of epochs inside
one call: it is not yet a durable subscription service across calls. Pursue a real
consumer before adding that lifecycle. Likewise, rational rewriting already
replays an egg explanation in a separate checker; extend its domain consumers
without folding search and checking into one trusted implementation.

The production worker now has an explicit entry point,
`tools/appliance/engine_worker.py`, with independent checkout and private-state
paths. The parity answerer remains a comparison tool. Packaging no longer
inherits its repository-relative state-directory requirement.

## Proposed batches and completion conditions

### 1. Make the host safe to compose and recover

The dispatch, deployment binding and tenant ownership repairs are implemented in
the current batch. The following original requirements remain the acceptance
criteria; the receipt records which have run. Cross-provider context transfer
and mixed-load measurements remain open:

- `Service::turn` asks the Engine before `journal.bind`; a later bind error
  propagates to `query`'s before-work error path, which forgets the pending
  request. Reproduce registry exhaustion/storage failure after a counted Engine
  action. Reserve conversation capacity before execution and retain uncertain
  results after execution. Exact retry must not repeat a changed turn.
- Bind host journals and cached results to admitted implementation/data/config
  identity. Decide explicitly how old records survive or refuse a release change.
- Separate tenant-private Engine state from shared public resources. A session
  name alone does not isolate learned/global state. Avoid an Engine per idle
  tenant; use bounded owned workers with explicit state export/reset boundaries
  until those state owners are extracted.
- Restore a killable containment boundary for providers that cannot guarantee
  bounded cooperative work. Share immutable mappings across bounded workers;
  do not trade the old pool's containment for a smaller-looking host process.
- Define cross-provider conversation behavior before claiming a complete turn.
  Native `/query` currently reads alone and Engine memory is separate.

Completion: focused fault-injection tests prove no duplicate execution, no private
state crossing tenants, and truthful reset/uncertainty on restart, saturation and
cancellation. Then Linux mixed-load tests measure whole-process-tree PSS, tail
latency and fairness. Astra reviews the combined state machine before deployment.

The current Mini packer constructs the archive in memory. The assembled debug
payload has about 1.31 GB of regular members and compresses to 165 MB. One
macOS signing run took 388 seconds with 4.19 GB peak RSS. Its explicit operator
profile changes admission ceilings, not manufacturing memory cost. Streaming manufacture
and release-build serving measurements remain performance work.

### 2. Integrate upstream interfaces and choose a release deliberately

Use isolated 10.1/10.2 candidates; leave qualified U8 intact. Compare the newly
exposed MCP/operation contract with our descriptors and exercise both actual
consumers. Source inspection finds `_validate` only checks top-level required
fields, unknown keys and basic types: advertised lengths, patterns, nested items
and numerical limits need portable adversarial checks and fixes.

Replay #6/#7 counterexamples through the whole head, including unaffected title
questions. Inspect dates for calendar validity, precision claims and ordering;
a label alone does not justify a numerical uncertainty interval. Measure the
new flash route separately with independent examples and preserve its empirical
status. Choose the release/profile only after those comparisons; no automatic
10.2 upgrade or silent removal of its new capabilities.

Completion: a compatibility map, focused regression results and a pinned candidate
whose exposed operations preserve evidence/refusal/state distinctions. Then build
and sign the Rust-host appliance and run the fresh Mini/Hermes agent/browser,
restart and exact-retry journey. This requires current Mini source orientation.

### 3. Turn the reader repair into useful answers

PR10 is posted and its eight source regressions pass. Retrain and re-export from
an isolated patched source, then compare code-only, data-only and combined against
the frozen 16/100 sets. Keep all expected facts, failures and declined questions.
After that, investigate packed demand-driven composition instead of accepting
large syntax enumeration as inevitable. An arena reduces storage; it does not
remove unnecessary work. New reading coverage needs independent questions, not
only agreement with the old reader.

### 4. Grow capabilities through real consumers

Build the next statistical specialist around the existing native provider and
score its actual supported tasks plus independent cases. Do not force unrelated
binomial questions through linear regression merely to fill a panel. Keep a
useful supplied-data agent operation even when old language templates are narrow.
Extend graph coverage where it earns capability beyond the existing 18/42.

For nonmonotonic reasoning, exercise evidence revisions, conflicting observations
and alternative plans through hosted calls; keep candidate actions separate from
execution authority. General astronomy, convex optimization, richer bio/statistics
and learned readouts remain open ambitions. Choose one substantive consumer at a
time rather than installing crates without users.

Maintained views remain an experiment, with both the negative small workload and
positive rooted-workload result retained below. Neither settles adoption. Formal
assurance and the older beyond-parity specialist backlog still need a current
audit; hosting progress is not completion of those obligations.
