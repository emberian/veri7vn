## What exists, and what actually failed

The native reader is already substantially demand driven. `lexicon.rs::LexicalWorkspace` shares indexed surface and negative lookups across the six whole/fragment/outer, level-0/1 modes without conflating their different alias/plural rules. `grammar.rs::match_whole` walks learned-template B-tree prefixes. `composition.rs::compose` first finds complete outer questions whose X holes are lexical-boundary regions; only those holes demand `segments.rs::Chart::region`. That chart interns steps/programs and region nodes in a request-local arena. `base`, `units`, `chains` admit exact learned fragments and segment chains; `region` adds one nesting pass whose children use `base`, deliberately excluding deeper recursion. Limits include 30-word fragments, 12-word units, four units and bounded region width. This is not a general CFG parser.

`Chart::resolve` filters independently admitted child programs, then explicitly enumerates their Cartesian product, flattens/rebases each nested program and interns the result. `composition::match_composed` ultimately returns `Vec<MatchedProgram>` with expanded programs and serialized provenance. `reader.rs::compile_candidate` JSON-encodes each program, then calls `program.rs::Program::parse` and `compile`. Typed operation contracts reject malformed arities, dependencies and literal kinds. This bridge repeats work that arena identity has already made shareable.

`query.rs::LanguageWorkspace` already canonicalizes complete typed nodes with canonical dependency slots; shared stages retain IDs, relation witnesses, attribute positions and qualifiers. Its typed attribute columns/indexes avoid decoding the same 548 source statements for hundreds of real predicate alternatives. `Demand::Exists` now serves fragment viability without fetching full reply evidence; `Count` exists but has no production caller. `reader::evaluate_inner` still requests Full for every complete candidate and retains a full `QueryResult` and flattened program in every successful reading. Answer text agreement and selection agreement are separate: identical text can answer, while divergent IDs/facts/attributes suppress persisted Previous. Forms veto all successful alternatives; unsupported/ambiguous executions block certainty. Support is admission data, not a winner-selection score.

`image.rs` builds immutable indexed nodes, parent membership, edges, attributes and grammar tables; worker leases own scratch SQLite state and cleanup. `query::compile` materializes every language stage, including dead branches. Ordinary explicit program execution uses final-DAG liveness instead. Therefore arbitrary dead-code removal or relational rewrite is not semantics preserving in reader mode. Relate uses source/predicate/direction adjacency and distinct objects; filters and joins carry statement witnesses. The existing image is already a useful relational execution substrate.

A faster parser must not bless this poisoned grammar or remove the form veto to improve a score.

## Three credible designs

**1. Carry the packed representation through typed compilation (recommended first).** Add a request-owned, typed program DAG keyed by `(operation, typed literals, canonical dependency IDs)`, with separate derivation witnesses keyed by lexical profile, level, region, learned row and child derivations. Reuse `Program` validation/contracts through an internal typed constructor; JSON remains the public boundary. Do not use JSON hashes as unverified equality or merge derivations merely because they have equal display answers. Keep required-child admission obligations even when a skeleton omits that child's result.

Replace eager flattened output with root handles and an explicit complete/exhausted state. A worklist compiles only demanded roots/dependencies; expansion is a diagnostic operation. A lightweight semantic outcome contains answer kind/value, canonical selection/evidence identity and refusal obligations. Hydrate one shared evidence object per unique outcome, with derivation IDs pointing to it. Preserve a bounded full-diagnostics mode for exact comparison. The runtime owns all handles within one request/lease; nothing survives image, Previous or normalization changes.

This removes repeated JSON compilation and reply duplication without promising to remove inherently different programs. Packed OR/AND recipes can postpone nested products, but “every combination agrees” generally still requires distinguishing combinations that change denotation. Early exit on disagreement is safe for a declined answer only if the contract permits incomplete diagnostics; early acceptance is unsafe until the admitted forest is exhausted. Resource exhaustion must remain distinct from success. Learned ranking may schedule complete alternatives, but dropping low-support suggestions cannot establish unanimity. A coverage premise must identify the admitted candidate universe and certify its exhaustive traversal; otherwise return a proposal/heuristic outcome, not a checked language answer. Even exhaustive learned-grammar coverage does not certify coverage of every meaning of English.

**2. Compile pure relational islands with demand and evidence obligations.** Separate extensional set computation from reader admission obligations. Within a proven-safe island, push selective concept/attribute conditions toward joins and represent common relation paths once; demand can be Exists, CountDistinct, identity set, typed scalar or full evidence. Maintain explicit statement handles until projection. A physical planner can choose indexed adjacency or membership-first intersection using measured cardinalities; start with SQLite and the existing image, not a new database engine.

An obligation ledger must still check the original reader's nonempty intermediate/child requirements, even if the optimized set computation bypasses them. Qualifier filters cannot float past a relation or attribute projection that changes their witness. Distinct entity counts must not become derivation/path counts. First optimize pure conjunctions with no qualifier-sensitive transformation. Relation planning is useful after measuring repeated *different* stages and join fanout; canonical memoization already solves identical stages. Current receipts do not establish a general join-planner bottleneck.

**3. Bounded recursive chart for deeper nesting.** Extend region recipes to memoized items `(region, requested result type, lexical mode, grammar policy)` and packed child alternatives; use an agenda rather than recursively expanding each parse tree. Initially require every recursive child region to be strictly shorter, eliminating cycles; later epsilon/same-span rules need SCC/fixpoint semantics and explicit resource bounds. Preserve learned grammar acceptance before adding content fallback or analogy. Recursion alone supplies no missing property, qualifier or English paraphrase. Reject a wholesale Earley/GLL replacement unless actual learned families require it: an incremental typed chart fits current code better.

[Goodman, *Semiring Parsing* (1999)](https://aclanthology.org/J99-4004.pdf), introduction and §2 item-based parsing/semiring discussion, shows that shared deduction structure and the values evaluated over it can be separated. Use explicit item/derivation structure and separate evaluation modes; do not replace all-alternative agreement with Viterbi or interpret support as probability. Its algebraic correctness conditions do not automatically cover this reader's unsupported-program veto, emptiness policy or mutable evidence selection.

[Olteanu and Schleich, *Factorized Databases* (2016)](https://www.cs.ox.ac.uk/dan.olteanu/papers/os-sigrec16.pdf), §§2–3 including variable orders and Figure 2, explains why storing unions/products and caching by dependency context can avoid flattening joins. Apply that to nested recipe choices and repeated evidence. Savings depend on conditional independence and variable order; a fully correlated alternative family may offer little compression. Counts over overlapping alternatives require canonical entity deduplication, not simply multiplying branch sizes.
