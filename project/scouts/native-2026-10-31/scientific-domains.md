## What actually exists

`native/oracle-science/src/lib.rs::linear` already accepts supplied matrices, uses serial thin SVD, distinguishes rank/consistency outcomes and recomputes residuals in original rows. Its declarations of units and assumptions are caller assertions. Limits are 512 rows, 128 columns and 32 MiB SVD scratch. `thermal.rs::thermal_network` is a real domain consumer, not merely an equation wrapper: positive conductances, named nodes, component grounding, expected topological rank, fixed ideal reservoirs, original-node power checks, floating-component heat balance and below-zero refusal. It constructs a dense Laplacian and invokes SVD. The current network cap is 128 nodes/1,024 edges. Existing checks and receipt are described in `project/lanes/NSCI-science-2026-10-29.md`; they are not a shipped thermal specialist score.

The extracted families remain useful foundations. `src/extract/space/Space.thy::request` enumerates circular speed/period, escape, synchronous and Hohmann operations, rocket equations, light time and table/year queries; it has no state-vector trajectory query. `stated_dec_sound` bounds rounding of an exact rational, while `to_dec_sound` assumes the actual value belongs to its input enclosure. Neither proves a real trajectory or an externally supplied constant is correct. `upstream/root/specialists/orbits/organ_orbits_v1.py` explicitly assumes ideal point-mass two-body motion and uses stored GM/radius/sidereal-period tuples. Its recognizer is narrow regex arithmetic, not an ephemeris.

`Mechanics.thy` contains unit conversion, gravity/work/efficiency and physical-domain guards; `energy/Calorimetry.thy` distinguishes heat and temperature intervals. `quantity/Quantity.thy` distinguishes absolute temperatures from differences and unsupported model conditions. Preserve these semantics when producing matrices. `geostats/GeoStats_Stats.thy` supplies descriptive statistics and combinatorics rather than physical uncertainty models. Chemistry's `stoich/Stoichiometry.thy::balanced_reaction_conserves_every_element` says a balanced parsed reaction conserves **every** element, including those absent from the listed symbols; stoichiometry does not establish rates, equilibrium or toxicity. A chemical-kinetics engine cannot infer a rate law from this theorem.

## 1. Passive network scenarios and sensitivity: strongest first increment

Concrete workflow: supply a board/building thermal network, compare heat-source or boundary-temperature scenarios, ask which resistance most affects a named hotspot, and distinguish disconnected or physically inadequate cooling paths. This extends the existing consumer instead of inventing another universal equation language.

Represent topology once as a canonical edge list and sparse compressed-column grounded Laplacian. Keep topology analysis, numerical factorization and result acceptance separate. For strictly positive passive conductances, each component connected to a fixed-temperature boundary has an SPD free-node block. That justifies sparse Cholesky **only there**. Floating blocks retain their freedom and balanced-source test; do not silently pin a node or use Cholesky failure as an exact inconsistency certificate. Keep the dense SVD route as a small-problem reference and diagnostic fallback.

Reuse symbolic fill analysis across unchanged topology, numeric factors across unchanged conductances/boundary membership, and factors across many right-hand sides. A changed conductance invalidates numeric factors; changed grounding invalidates the reduced system; topology changes invalidate symbolic analysis. Cache identity must include canonical node order, boundary membership, values and numerical policy. No tenant-shared mutable workspace or unbounded factor cache. Sparse fill can exceed dense memory on unfavorable graphs: account for estimated/actual fill and reject before exhausting host budgets.

For a grounded solve `L(p) T(p)=b(p)`, compute parameter derivatives from `L dT/dp = db/dp - (dL/dp)T`. For one scalar target and many parameters, solve the transposed adjoint once and contract each edge derivative. No matrix inverse. Return named parameter units, Jacobian units and domain assumptions. This makes sensitivity an interpretable physical answer and avoids repeated finite-difference solves. Unknown conductance times unknown temperature is bilinear; this is forward sensitivity about supplied parameters, not a convex inverse-design guarantee.

Use local Jacobians for statistical covariance propagation only when a sampling model is supplied. Deterministic tolerance boxes are different; corner sampling is not an enclosure for arbitrary networks. Until a justified interval/monotonicity method exists, label bounded scenario sweeps as sampled scenarios. A conductance's effect on an arbitrary node temperature need not have a universal sign.

## 2. Transient storage networks with controlled integration

Concrete workflow: “after this heater turns on, when does the component exceed 340 K, and how does added thermal mass change that time?” Add positive finite heat capacities in J/K and initial absolute temperatures to the existing conductance model: `C dT/dt = q(t) - L T + boundary forcing`. Begin with fixed topology, constant conductances/capacities and piecewise-constant prescribed inputs. Zero-capacity algebraic nodes introduce a DAE and deserve a separate contract rather than division by zero or an artificial tiny capacity.

A diagonal positive C and passive L yield dissipative free dynamics. For an isolated network, total stored energy changes by applied heat; internal exchanges cancel. Relative to a fixed equilibrium, quadratic storage decays without forcing. Report original energy balances and temperature-domain checks, not just a solver success flag. These are model/numerical diagnostics, not proof that the supplied lumped parameters describe a real object.

Compare a transparent backward-Euler/step-doubling baseline with a stiff BDF or SDIRK implementation. Backward Euler preserves useful monotonicity for this model but is only first order. Adaptive local error estimates are not rigorous global enclosures. Component tolerances must have K units; event-time error additionally depends on crossing slope. Stop at source discontinuities and restart integration consistently. A tangential threshold contact can be missed by sign-change detection, while chattering thermostats need explicit hysteresis and event-count limits. Return “no crossing found over this interval” with detection assumptions, not an unconditional absence theorem.

Forward sensitivity equations can share linear solves for a few parameters; adjoints suit a few outputs and many parameters but introduce checkpoint ownership and replay cost. Start with forward sensitivity and fixed schedule, defer switched-system derivatives: event/reset derivatives require extra terms, not differentiation through an unchanged schedule.

## 3. Ideal orbital trajectories and event queries, with honest astronomy time

Concrete workflow: supply a state vector around a named central body, propagate an ideal eccentric orbit, locate periapsis or a radius crossing, and cross-check a Hohmann result as a trajectory. This extends the existing orbital formulas materially. It is not a real spacecraft prediction with drag, oblateness, third bodies or maneuvers.

Require central-body GM and provenance, length/time units, frame and origin, epoch and time scale. Use a typed instant and a duration in SI seconds; keep a split day/fraction representation through arithmetic. UTC civil input requires a versioned leap-second table; Earth-fixed transforms additionally need Earth-orientation data. Missing data must produce a specific refusal. TT/TDB/UT1 are not interchangeable spellings; an unqualified date must not silently become all three.

First compare a bracketed two-body universal-variable propagator with an independent adaptive integration reference. Use robust near-parabolic handling rather than separately fragile elliptic/hyperbolic formulas. Track specific energy/angular momentum drift and forward/backward recovery, but recognize conserved wrong trajectories can pass those tests. Independent analytic circular/elliptic cases and event locations are necessary. A symplectic fixed-step method may be valuable for long integrations; it is not automatically best for short threshold-event accuracy or nonconservative forces. Do not add a full astrometry crate merely to answer existing altitude formulas.

## Literature and feasible reuse

Fresh primary reading: Machado, Cucuzzella and Scherpen, [Modeling and Passivity Properties of Multi-Producer District Heating Systems](https://arxiv.org/abs/2011.05419), 2022 revision, §4 assumptions and thermal equations plus passivity statements. Its fluid model neglects conduction and carries advective heat with flow: **it does not validate replacing district-heating pipes with symmetric conductance edges**. Simonsson, Tourkey Atta and Birk, [Reduced-Order Modeling of Thermal Dynamics in District Energy Networks using Spectral Clustering](https://arxiv.org/abs/2202.09259), 2022, introduction/§II, likewise motivates physically informed reduction rather than generic graph coarsening. Defer reduction until unreduced consumers and output-error questions exist; its reported case performance is not an Oracle benchmark.

[IAU SOFA's Time Scale and Calendar Tools](https://www.iausofa.org/s/sofa_ts_c.pdf), read §§1.5, 2.3–2.4 and time-scale discussion, gives the operational model for split Julian dates, leap-second handling and explicit conversions. Treat SOFA examples as an external reference, with table provenance retained, rather than asserting a new implementation inherits SOFA accuracy.

Current project documentation verified: [faer 0.24.4 SymbolicLlt](https://docs.rs/faer/latest/faer/sparse/linalg/solvers/struct.SymbolicLlt.html) supports reusable symbolic sparse LLT; already-pinned faer is the most economical candidate. [Diffsol 0.18.0](https://docs.rs/diffsol/latest/diffsol/) documents BDF/SDIRK, sparse faer matrices, events and sensitivity controls. ## Sequence, rejection tests and boundaries

First expose a supplied-network scenario consumer using current caps; compare dense and sparse candidates on chains, stars, grids and deliberately high-fill graphs. Preserve original-node acceptance. Reject sparse expansion if memory/factorization overhead dominates at supported sizes. Next add analytic derivatives and check them against independently derived one-link/two-node formulas plus convergent finite differences away from singularity. Near disconnection, large sensitivity is a physical warning, not a value to hide with rank thresholds.

Then transient single-node exponential cooling, two-node closed-system energy conservation, separated time constants, forced discontinuities, grazing events and nonphysical cooling below zero. Tightening tolerance must show convergence to analytical solutions; conservation alone is insufficient. Finally orbital circular/Kepler examples, near-parabolic continuity, leap-second boundary conversion, deliberately mismatched frames and missing Earth-orientation data. These experiments precede any enlarged production caps. Every admitted prose adapter must run its shipped specialist panel plus independent truth cases; new workflows need new panels and scorers. No current result substitutes for those numbers.
