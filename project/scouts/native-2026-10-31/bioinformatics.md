# Bioinformatics: supplied sequence collections before another aligner

Research/design only, 31 October 2026. No implementation, builds, tests, or new panel measurements. No new theorem statements. Historical shipped held-out verdicts read directly: biology **15/15 correct, 0 wrong, 0 false yes**; genetics-v2 **15/20, 0 wrong, 0 false yes**; microbiology-v2 **13/13, 0 wrong, 0 false yes**. These are upstream comparison numbers, not qualification of this proposal or the native extension.

## What runs today

`native/oracle-bio/src/lib.rs` exports `align_pairwise`, `check_alignment`, `call`, and `catalog`. `admission` rejects malformed alphabet/scoring and admits at most 4096 bases/string, 1,048,576 DP cells including borders, and a 16 MiB buffer estimate. These constraints combine: two 4096-base strings are not admitted. `align_pairwise` normalizes ASCII, asks pinned Rust-Bio 4.0.1 for global/local/query-global affine alignment, drops its traceback matrix, and invokes `replay`. Replay checks coordinates, consumption, edit labels and score, then `optimal_score` independently recomputes optimality with four rolling i64 rows. This is checked computation, not an Isabelle theorem. Both passes are quadratic; the provider is serial, stateless, and cannot interrupt Rust-Bio internally.

`tools/oracle_components/native_bio.py::NativeBioOperations` declares the structured operation and validates returned score agreement. It is an explicitly untrusted Python adapter. Neither component imports records, keeps an index, searches the opposite strand, or supplies protein/biological interpretation. Replacing only the proposal algorithm leaves the quadratic independent checker intact.

The actual `upstream/root/specialists/biology/organ_biology_v1.py` already implements complement, reverse complement, transcription, standard-table translation and GC. Translation takes the frame from the first supplied base and stops at the first stop; `_seq` and `clean` are sentence-oriented extraction, not a lossless sequence parser. Genetics-v2 handles crosses and equilibrium arithmetic; microbiology-v2 handles growth/dilutions. Their consumers should remain distinct from sequence search. The native README's future-work list is sensible, but retained data and complete-search semantics are the missing substrate.

## Three connected consumers

### 1. Find every exact supplied fragment, then batch approximate matching

A user supplies a FASTA collection and asks “which records contain each of these fragments, in either strand, and where?” Return record identity, strand, original zero-based half-open interval, exact matched bytes and collection digest. Start with exact ACGT search; reject or explicitly split ambiguity runs. Declare whether reverse-complement palindromes count once or twice. Duplicate FASTA identifiers are labels, never keys. Empty query and circular-wrap searches need separate policies.

Represent `SequenceSet` as immutable normalized byte arena plus parallel arrays of record offsets, lengths, name offsets and original-source digests; retain normalization policy and record order. `Arc<SequenceSet>` shares input ownership. Keep ASCII initially: it simplifies replay and preserves ambiguity; add two-bit storage only after measuring, with a separate ambiguity mask. No accidental matches across concatenated record boundaries.

For repeated queries, use sorted observed packed k-mer keys and compressed posting ranges `(record, position, orientation)`. Choose one exact query seed, preferably the least frequent, and verify full bytes at every posting. Queries shorter than k use a bounded scan. Building O(total bases) postings has a visible size cost; sorting and scratch buffers must also fit admission. Deterministic ordering allows paging without retaining a giant answer vector.

The locally installed Rust-Bio `data_structures/qgram_index.rs::with_max_count` allocates both `address` and temporary `offset` proportional to `4^k`, plus occurrences. It is suitable only for explicitly tiny k; frequency masking silently drops seeds and cannot support “all occurrences” without fallback. Its `matches` API is a seed match object, not proof of a full-query occurrence. Prefer direct postings and byte verification over exposing that convenience API.

For approximate short-fragment searches, existing `bio::pattern_matching::myers::{Myers,long::Myers}` is a credible first backend: unit insertion/deletion/substitution cost, explicit threshold, complete record scan, optional path only for reported hits. Cache a query profile per worker, stream reference records, and keep scratch worker-local. Source documentation has an important endpoint difference: `find_all_end` returns an inclusive end index; `find_all` returns a half-open range. Normalize at the adapter. Decide whether the public result enumerates every qualifying endpoint with one best path, or every qualifying start/end interval; those are different tasks.

Completeness requires every admitted record and position to be covered, including repetitive seeds. A result cap produces `truncated` plus a continuation token, never a complete zero count. Replay checks positives; a separate full scan on bounded cases checks omissions. Production absence still relies on index construction/coverage, not only positive-hit replay.

### 2. Compare batches and shortlist large supplied collections

A second consumer asks for exact edit distances between supplied pairs, or a shortlist of similar records before detailed alignment. Give unit edit distance its own operation and result type. Reusing the current affine operation would conceal a different optimization problem. Use score-only requests by default, then recover bounded paths for selected pairs. An independent threshold-banded scalar DP can check a proposed global distance d: any unit-cost path of cost at most d stays within diagonal distance d, and recomputation within that band must return d. This reduces checking work on similar strings; worst-case quadratic behavior remains. A resource refusal is not an “over threshold” answer unless the threshold decision actually finished.

[A*PA2 (Groot Koerkamp, WABI 2024)](https://curiouscoding.nl/papers/astarpa2.pdf), sections 1.1–2, combines bitpacking, blocks, incremental threshold expansion and an admissible seed heuristic for exact **global unit edit distance**. Its four-letter encoding and SIMD assumptions require portability evaluation. It is a later contender for long similar pairs, not a drop-in for affine local alignment. Prefer the already pinned Myers machinery for the first short-query consumer; avoid adding two large alignment systems at once.

For larger collection discovery, optional FracMinHash signatures store sorted sampled hashes plus k, hash algorithm/seed, molecule type, sampling scale, abundance policy and source digest. Exact intersection arithmetic on stored hashes yields a sketch statistic; it does not establish full-sequence containment. Separate shortlist candidates from complete sequence-search answers. Never use an empty sketch to claim absence.

[Branchwater (Irber, Pierce-Ward, Brown, 2022 preprint)](https://dib-lab.github.io/2022-paper-branchwater-software/manuscript.pdf), Background and Methods, provides a useful ownership recipe: shared immutable query sketches, stream subjects, release per-subject state, and send results to a writer. Reuse sourmash's Rust sketch compatibility machinery if this consumer is selected; do not inherit public-database/taxonomy behavior. Its paper explicitly identifies poor suitability for short queries at the chosen sampling scale. No petabase infrastructure is justified for the initial supplied collections.

Minimizers serve a different purpose: position-bearing sparse seeds for candidate generation. [SimdMinimizers (Groot Koerkamp and Martayan, SEA 2025)](https://drops.dagstuhl.de/storage/00lipics/lipics-vol338-sea2025/LIPIcs.SEA.2025.20/LIPIcs.SEA.2025.20.pdf), sections 2–4, motivates packed sequences and predictable two-stack sliding minima. It also distinguishes canonical *window selection* from merely canonical k-mer values. Record tie rules, parameters and orientation; test reverse complements, repeats and chunk overlaps. Hash agreement alone is never exact occurrence evidence. The project supports AVX2 and NEON; audit scalar fallback and feature requirements before choosing its crate. No reason to insert minimizers ahead of complete short-fragment scanning yet.

For affine long-pair work, [Singletrack (López-Villellas et al., Bioinformatics 2026)](https://webdiis.unizar.es/~chus/pubs/2026_Bioinf.pdf), sections 2–5, reconstructs omitted gap matrices during traceback and integrates with WFA2. It improves storage against particular baselines, not every compact traceback implementation. Rust-Bio already keeps compact traceback. WFA2's C/FFI boundary, scoring conventions, optional heuristic pruning and memory modes need separate admission/checking review. Keep the current affine backend until an actual consumer exceeds it; measure proposal plus checker together.

### 3. Translate annotated intervals while retaining their source coordinates

A teaching or sequence-curation consumer supplies records plus explicit coding intervals/strand/frame/table, asks for proteins and codon-to-source maps, then searches those outputs. This extends existing biology utilities through composability: every amino acid refers back to three source positions and the declared translation policy. Flat feature arrays `(record,start,end,strand,phase,table)` borrow the immutable set; output protein bytes and compact coordinate mappings own only derived data.

Require a named versioned genetic-code table, partial-codon policy, internal/terminal stop policy and explicit feature order. [NCBI's genetic-code tables](https://www.ncbi.nlm.nih.gov/Taxonomy/Utils/wprintgc.cgi) distinguish translation tables and initiation behavior; the standard code is not universal. Start with contiguous complete intervals. Add split CDS/GFF3 only after specifying phase across joined pieces and reversed feature order; a file parser cannot choose those semantics. Noodles offers FASTA/FASTQ/GFF support, but select modules rather than importing BAM/VCF scope. No inferred genes, protein function, variant significance, diagnostic claim or organism assignment follows. Phylogenetic inference is deferred: sketches or an alignment do not supply a substitution model, trustworthy multiple alignment or tree uncertainty.

## Phases, rejection criteria and interfaces

First deliver the immutable sequence contract, exact search and paging; create a specialist panel that composes import → query → original-coordinate answer. Keep shipped biology/genetics panel scores separate and add independent truth cases. Next compare short Myers scans against naive scalar substring DP; only then try long global distance and optional sketches. Annotated translation can share the collection contract without depending on approximate search.

Decisive counterexamples: identical names/different content; seed crossing a record boundary; all-A repeats overflowing postings; N-runs; reverse-complement palindromes; hits exactly at chunk edges; threshold ties; distance paths with long gaps; code-table-dependent stop codons; reverse-strand interval mapping. Compare indexed output to complete naive enumeration on small generated collections, including omissions and paging concatenation. Compare distances to independent scalar DP and replay paths. Measure wall time, peak RSS, index-build cost, output bytes and cancellation latency at fixed batch/base budgets. Reject indexing when construction dominates reuse; reject sketches when short queries routinely disappear; reject faster proposals whose checking dominates or whose CPU restrictions exclude supported hosts. No benchmark result is claimed here.

Host/schema scouts must supply content-addressed collection handles, lifetime/eviction and source coverage, byte/output admission and one concurrency budget. Parallelize independent records/pairs, with bounded queues and reusable worker scratch; do not create nested Rayon pools. Open choices for root: initial collection size, whether persistent indices have a real consumer, and endpoint versus interval enumeration. These are engineering choices to resolve with the first panel, not biological facts to infer.
