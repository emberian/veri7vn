# Data-oriented native execution

Research/design only, 31 October 2026. No implementation, builds, tests or commits. **Panel numbers: none from this lane.** Recommendation: typed provider calls first, bounded typed query batches second; retain the current external JSON contract. Measure each separately before changing storage or adding compilation.

## What actually runs

`native/oracle-host/src/pure.rs::Pure::invoke` receives a `serde_json::Value`, clones incremental arguments or builds a fresh operation envelope, calls `wire::encode`, converts bytes to `String`, dispatches a string API, and reparses the reply through `parse_reply`. `Structured::{science,statistics,bio,incremental,logic}` then interprets JSON fields into the host reply. Reasoning has a separate branch but also builds and encodes an envelope. Thus linking Rust crates into one process has removed Python without removing serialization between components.

The providers already have useful typed seams: `oracle-science::linear` (and `thermal::thermal_network`), `oracle-statistics::regress`, `oracle-bio::align_pairwise`, and `oracle-incremental::{evaluate,recompute}`. Their `call`/`call_json` functions primarily decode, dispatch and serialize. Science/statistics use boxed `RawValue` arguments to avoid the serde buffering issue documented beside science's `Request`; direct deserialization is not automatically behavior-equivalent under the workspace's arbitrary-precision number configuration. `oracle-reasoning::call` builds an intermediate JSON reply even when its underlying calculation returns a typed result.

`oracle-python/src/providers.rs` exposes string-to-string wrappers, detaches Python execution, and creates uncancelled default flags for science/bio/statistics. `oracle-python/src/lib.rs` holds core runtime/image objects in `Arc` and invokes their JSON APIs while detached. This is a second boundary, not justification for forcing Python objects into the native kernels.

Core is already partly data-oriented. Reader `compile_candidate` currently encodes `MatchedProgram.program` and reparses it through `Program::parse`; a direct checked typed conversion is another concrete seam. Coordinate with the reader scout to preserve packed candidate sharing until admission, rather than repeatedly flattening every candidate. `program.rs` compiles a closed typed program into a shared entity DAG. `query.rs` uses string-ID `BTreeSet`s, SQLite temporary sets and fact tables; `LanguageWorkspace::filter_column` caches parsed `(AttributeFact, TypedValue)` rows by input stage and attribute key, with a string-equality index. It retains source positions and qualifiers. But loading a column still constructs source strings, parses attribute JSON into `Value`, then constructs exact typed values. `TypedValue` serialization itself constructs a JSON value. These are specific allocation sites, not evidence that every operation needs a column store.

`Image` already shares admitted immutable image identity via `Arc` while leasing bounded SQLite connections. `Budget` already combines fuel, absolute deadline and wakeable cancellation. Host `service.rs` presently bridges core cancellation and a provider atomic flag; it retains the worker capacity slot after timeout until cooperative execution returns. Preserve that protection.

## Three designs and their fit

### A. Typed islands with wire adapters — first choice

Each provider owns its small operation-specific request/result types. Host dispatch selects an admitted operation and converts validated arguments once into the provider input; it calls the typed kernel and interprets typed output. Existing string APIs become wrappers around that same entry point. Do not introduce one enormous cross-project `OracleValue` enum. Domain types already distinguish alignment inputs, regression assumptions and exact scientific values better than such an enum could. Units must carry their semantic basis: `oracle-reasoning/src/dimensions.rs::DIMENSION_ORDER` has seven SI coordinates including amount, whereas `src/extract/fusion/Fusion.thy::d_money` uses the sixth of six coordinates for money; conversion requires a checked named mapping, never a tuple cast.

An internal adapter should return a typed domain result plus typed refusal information, keeping transport failures separate. A host adapter then constructs the exact existing public envelope. Share the decision logic between typed and wire interpretation during migration so they cannot silently disagree about missing fields, refusal codes or evidence. Retain descriptor/catalog identity checks, tenant checks, declaration validation and reply admission even when the producer is in-process: handwritten Rust remains unverified.

Initially converting `&Value` to owned provider inputs is acceptable. It eliminates a stringify/parse pair without complicating lifetime ownership. Later allow borrowed text/slices in hot inputs where useful, with ownership explicit when a call is queued. Small scalar calls stay scalar. A batch of regression observations is one natural typed array, while one answer about a constant is not an Arrow record batch.

### B. Bounded query batches and scoped identifiers — complementary second step

Extend the existing attribute workspace rather than replace SQLite. Introduce image-scoped `EntityId`/`PredicateId` newtypes with reverse dictionaries; request-local indices identify statements and scratch objects. Public IDs remain unchanged. An ID's scope is the image digest, not just its integer: equal integers from different images must never join. Initially intern only repeated keys and selected IDs in the request; an offline image dictionary is a separate, versioned image-format experiment.

Use sorted ID vectors or bitmaps only after measuring selection density; sparse sets, dense sets and ordered external output have different costs. Keep statement multiplicity separate from entity-set uniqueness. A matching subject may have several distinct values or qualifiers; collapsing those statements would change answers.

A useful batch has contiguous subject IDs, statement positions, type tags, optional validity/unknown masks, and references into typed value/qualifier arenas. Numeric/date/string partitions can have specialized loops. Big rationals live in owned side storage; do not coerce them into floats or fixed Decimal128 merely to fit a column format. Year precision and day precision remain distinct. Preserve the original lexical literal for evidence and bounded formatting. Batch source rows once, reuse parsed values across predicates, and materialize final source text only where the consumer needs it. Forbid a batch from outliving its request arena unless it owns an immutable buffer handle.

Tune a bounded chunk by bytes as well as row count, starting with experimental row sizes such as 64/256/1024; variable-size exact values make one fixed “cache-sized” row count misleading. Check cancellation between chunks and within expensive scalar operations. Do not materialize an entire source column merely to demonstrate vectorization. A tiny lookup should continue using an indexed SQLite query.

### C. Compile repeated plans — defer pending a profile

Cache validated typed plans and resolved operation/key IDs by image digest, compiler/semantic version and admission policy. This removes repeated parsing and name resolution without machine-code generation. Fuse repeated filter loops only where the plan and semantic checks permit it. Full JIT adds executable-memory, compilation latency, cache eviction and cancellation questions; it is credible for stable repeated large scans, but there is no measured evidence here that it beats A+B for current specialist requests. It also cannot fix source incompleteness or a wrong mathematical model.

## Ownership and execution context

Use three ownership levels: `Arc<Resources>` for immutable catalogs, dictionaries and admitted artifacts; a worker lease for SQLite connection and reusable bounded scratch capacity; and a request-owned arena for text/value/provenance buffers. Return owned bounded results or a handle owning their buffers. Never return SQLite row borrows, scratch references or Python-owned mutable buffers past a detached call. Reuse capacity only after the prior result relinquishes it; cancellation must drop allocations and release leases through the same path as ordinary completion. Avoid one global locked interner: attacker-controlled text would become permanent state and tenants would contend.

A shared `ExecutionContext` should carry the existing core `Budget`, cancellation bridge, resource view and allocation/output accounting. Provider-local semantic ceilings remain, intersected with host policy. Nested calls inherit the same deadline and shared fuel; they must not mint fresh default budgets. Precharge checked allocation sizes before allocating, charge actual rows/bytes and expensive numeric work, and bound serializer output too. Timeouts are cooperative; no context type makes a nonchecking external solver preemptible. Keep external solver process containment and the host slot rule. Context interfaces should unify existing mechanisms rather than create a second competing scheduler. Keep `SessionTurn` and explicit authenticated state owners intact; include pinned image/catalog/coverage versions and committed evidence revision without moving session commit or delivered-answer lineage into scratch context. Solver atom IDs remain snapshot-local; external evidence IDs are namespaced and stable.

Python keeps its current JSON functions for compatibility. A later explicitly separate batch API can accept owned native data or validated read-only buffers. Strides, endian, alignment, dtype and concurrent mutation need an admission rule; borrowing a writable NumPy array while Python is detached is not safely immutable merely because Rust receives `&[T]`. A defensive copy is the initial recommendation. Arrow C sharing is optional for large table interoperability, not the internal scalar API.

## Literature translated into decisions

* [Boncz, Zukowski and Nes, 2005](https://www.cidrdb.org/cidr2005/papers/P19.pdf), targeted reading §4–4.1 and surrounding materialization discussion: vector-sized incremental processing offers a middle ground between per-row interpretation and complete column intermediates. Application: bounded attribute batches and reuse of parsed columns. Their historical hardware and analytical workload do not establish Oracle's batch size or speedup.
* [Neumann, 2011](https://www.vldb.org/pvldb/vol4/p539-neumann.pdf), targeted reading §3.1 and §4: data-centric pipelines reduce transfers between operator boundaries. Application: fuse admitted predicate work around shared typed values. A Rust enum interpreter or native binary is not thereby a compiled query engine; measure dispatch/materialization before JIT.
* [Kersten et al., 2018](https://www.vldb.org/pvldb/vol11/p2209-kersten.pdf), targeted reading §3 methodology, §5 SIMD and discussion: compare execution models with the same physical plans, algorithms and structures. Their principal execution comparison excludes compilation overhead. Application: use equal-work comparisons and include end-to-end cold latency here; vectorization and compilation can both be credible, with no universal winner inherited from their results.
* [Arrow format](https://arrow.apache.org/docs/format/Columnar.html) and [C data interface](https://arrow.apache.org/docs/format/CDataInterface.html), targeted ownership/layout reading: contiguous arrays, offsets, dictionaries and explicit release ownership are useful at table boundaries. Zero-copy describes compatible existing layouts, not conversion from JSON or SQLite strings. The C interface is same-process interchange, not persistence or cross-process transport. Do not let its physical types redefine Oracle's exact semantic values.
* Existing paperbin: `~/paperbin/oracle7-20261027/relations/razniewski2023-completeness-survey.{pdf,txt}`, targeted §2.1–2.2. Incomplete source knowledge constrains counts and negatives regardless of execution layout. Batches must carry statement witnesses and preserve coverage premises; “no row in batch” never becomes a universal negative.

Three focused Kagi searches and three Scry title lookups were recorded in lane scratch. Initial Scry ILIKE predicates were rejected; corrected indexed `lower(title) LIKE` queries succeeded, including Neumann and Kersten bibliographic matches. Initial PDF retrieval failed local certificate verification; using the installed CA bundle succeeded. New PDFs, extracted text, hashes, source URLs and reading-depth manifest are in `~/paperbin/oracle-native-20261031/data-execution/`; no papers enter git.

## Reversible experiments and rejection criteria

1. Instrument conversion/allocation counts and elapsed time at host decode, provider decode, kernel, interpretation and final encoding. Compare old and typed routes for science linear and bio alignment, including 1-row/tiny inputs and bounded large inputs. Require unchanged success/refusal semantics and specialist panel scores; independently check equations/alignment witnesses. Reject a claimed performance win if expensive kernels dominate and confidence intervals overlap. Allocation reduction alone may still simplify the design, but say so.
2. Run existing workspace versus bounded batches on repeated predicates over the same source column: rare string equality, dense numeric range, mixed date/year, large rationals, qualifiers and duplicate statement positions. Compare full evidence and stable output ordering, not just selected entity count. Sweep batch sizes, selectivity and input scale; record peak resident/retained bytes, allocations, p50/p95 latency and cancellation delay. Reject batches that increase tiny-query latency materially or duplicate retained memory without useful throughput.
3. Differential adversarial wire cases: duplicate object keys, unknown fields, missing/null distinctions, giant exact integers/exponents, trailing bytes, non-finite numbers, Unicode normalization/casing and encoded byte ceilings. Host `wire.rs` deliberately rejects duplicates and preserves numeric source literals. Ordinary serde decoding must not bypass those policies. Count wire bytes at ingress and enforce the historical provider request/reply bounds even after removing internal serialization; otherwise the “optimization” widens admission.
4. Cancel while waiting for a worker, parsing, building a column, comparing a large value and encoding output. Repeated requests must not grow interners/scratch or release a capacity slot early. Run cross-image integer-ID collision cases and two tenants sharing an image. Partial/cancelled results must never acquire complete-coverage status.

Interfaces needed from sibling scouts: capability operations and evidence/refusal contracts; immutable image versioning; solver containment and cost units; provider semantic audits. Open selection question for root is workload priority, not whether JSON can be removed everywhere: profile specialist calls and repeated structured programs separately. No benchmark or panel improvement is claimed by this report.
