# State and resources: semantic records, shared corpora

Research/design only, 31 October 2026. **No specialist-panel numbers yet.** No implementation, build, test, deployment or Mini work was performed. Proposed examples below are acceptance cases, not results.

## What actually owns state today

`native/oracle-core/src/image.rs::Image` already supplies a useful foundation: one admitted image hash, `Arc<Image>`, and a fixed pool of read-only SQLite connections. `Image::open` configures per-connection page-cache and mmap limits and creates private TEMP tables for selections. `acquire` leases a connection and excludes a second simultaneous request for the same tenant. This bounds connection count by worker capacity rather than tenant count. File-backed pages may be shared by the operating system; SQLite caches and TEMP contents still require accounting.

`runtime.rs::Runtime` owns that image plus `StateStore`, a cancellable lease over one state connection. Its sessions table is keyed by tenant/session and records image, revision and state. Requests have tenant-scoped IDs, request digests and exact replies. Execution checks the replay journal before acquiring an image worker; reads the expected session revision; evaluates; then commits selection and exact reply transactionally. This is substantially stronger than a worker-local cache. The current native reader consumes the previous selection; it does not automatically inherit arbitrary Python dialogue state.

`session.rs` is already schema 2, not an empty placeholder. It defines namespaced referents, dialogue subject/answer/topic, prior numbers with exact-decimal versus Python-float origin, pending interpretations, delivered-answer/physics/effect lineage, bounded owner/version extensions, and tenant/session/image binding. `SessionTurn` makes a private draft, consumes pending interpretation speculatively, and rejects commit if the complete base changed. Missing Oracle state is explicitly unavailable. Its comments correctly deny whole-Engine isolation. However, string units, a boolean `is_person`, arbitrary conversion JSON and owner extensions are serialization contracts, not a complete domain model. Drafts also clone the envelope more than once; keep them small before optimizing those copies.

`native/oracle-host/src/engine.rs::EnginePool` follows a different contract: each bounded slot belongs to one tenant for a whole process generation. Eviction destroys memory and never imports old files. Its admission says `state_export:false`, and its module comments explicitly promise fresh replacement conversations. It does not provide durable cross-provider dialogue. `tools/appliance/tenant_pool.py` similarly documents a separate Service/EngineProcess per resident tenant.

The actual U8 materialization is `var/appliance-20261029/candidate-u8/`. Its `oracle7.py::Engine` creates a dedicated one-thread executor because the runtime's stores are thread-bound. `root/wander-train/chat_context_v2.py` keeps module-global `_STATES`, capped at 2000; `Turn` contains question, subject, answer, result, solved, material and topic. The admitted `runtime_conversation_state.py` borrows a global entry for one serialized turn, restores ambient state in `release`, and copies committed context into runtime `_conversation_contexts`. `finish` reconciles context with the delivered reply, clearing unsupported numerical state. It can evict an older context when the cap is reached. `oracle_release_runtime_an.py` separately owns `transitions` and `_pending_conversion`; its continuity check requires an introduced term grounded in the prior turn. Copying only `Turn` therefore loses real behavior, while copying the entire Engine duplicates unrelated stores and handles.

## Three designs and the recommendation

**1. Semantic session records over immutable images — recommended.** Keep a process-wide image registry keyed by admitted content digest and capability/coverage manifest. Each session owns only identity, revision, selection references, bounded discourse, pending interpretation and lineage. A provider receives an immutable `TurnInput` and returns `AnswerCandidate` plus a typed `ContextDelta`; the dispatcher commits only the winning delivered answer. A candidate that loses arbitration cannot change the next pronoun or quantity. Durable mutation acknowledgements and answer computation must be distinct where a reasoning-ledger write succeeds but solving later times out.

A referent should carry `(namespace, identifier, corpus_revision)` and optional evidence-backed type claims. Label and grammatical preference are presentation/discourse fields, never identity proofs; `is_person` is insufficient for uncertain or conflicting classifications. A quantity needs exact rational/decimal or explicit rounded interval, unit dimension and scale/offset, source precision, origin and answer revision. Preserve imported float spelling without pretending it recovers exact source precision. Solved variables additionally need expression/scope identity. A pending rewrite records input, proposed interpretation, originating turn, supporting referents/quantities, intended consumer and single-consumption policy. An acknowledgement must not silently replay an old operation. Answer lineage references the delivered result and its assumptions, not a speculative route's response string.

This gives reader → arithmetic → unit conversion → reader follow-ups one contract. “What is its population?” uses the established entity ID; “divide that by two” consumes a dimensioned quantity; “why?” follows delivered lineage across providers. Unsupported references produce an explicit clarification or refusal rather than stale substitution.

**2. Owner-scoped Python compatibility records.** While extraction proceeds, export/import only declared session owners at the serialized turn boundary. Migrate `chat_context_v2.Turn` and `_last_value` first; then pending conversion/AN transition history; then individually specified discourse and answer owners. Each owner declares read/write/reset semantics, maximum bytes, schema version and completeness. Import absence only when the exporter actually observed absence. This is an incremental bridge, not permission to multiplex arbitrary Python Engines between tenants. Hidden globals, handles and background loading still defeat reuse; retain tenant-bound fallback workers until the remaining owner inventory is understood.

**3. Fork/checkpoint warm Python templates.** Potentially amortizes imports through copy-on-write but is a secondary experiment. Capture must precede tenant state, threads, SQLite ownership and external effects. U8 currently builds its runtime on a dedicated executor thread; a copied memory image is not a correct restoration of that lifecycle. Shared pages can become private under Python allocation/refcount activity. Reject this route if private-memory growth or restoration complexity exceeds the semantic-record path. Do not make it a prerequisite for useful native conversation.

## Literature translated into decisions

Existing paperbin papers were reused, not duplicated. Boki (Jia and Witchel, SOSP 2021), sections 3/5 and the Beldi integration discussion, distinguishes authoritative ordered records from disposable auxiliary/view caches. Read those body passages in `~/paperbin/oracle7-20261027/hosting/papers/boki-2021.txt`; source: [author PDF](https://www.cs.utexas.edu/~witchel/pubs/jia21sosp-boki.pdf). Apply the distinction locally: committed session/ledger and exact retry records survive eviction; derived reader/solver caches do not. Boki's distributed protocol and exactly-once workflow machinery do not follow automatically from adding a SQLite table.

SOCK (Oakes et al., ATC 2018), initialization and cache sections, read selectively in the existing `sock-2018.txt`, supports separating installed packages, interpreter templates and invoked handlers; [publisher PDF](https://www.usenix.org/system/files/conference/atc18/atc18-oakes.pdf). Oracle's immutable corpus is the safest sharing boundary. That paper does not establish safe copying of U8's live threaded Engine.

Fresh primary documentation read: SQLite [isolation](https://www.sqlite.org/isolation.html), [memory mapping](https://www.sqlite.org/mmap.html), and cache-size section of [PRAGMA](https://www.sqlite.org/pragma.html#pragma_cache_size). Separate connections see committed transactions; WAL supplies snapshot reads but still has one writer. Read-only immutable corpus images avoid a mutable corpus snapshot protocol. Mmap can avoid duplicate page copies but can be slower, and I/O faults can become process signals. Cache-size is a suggested cache bound, not a whole-process memory guarantee. These sources support measuring both mapped/file pages and private allocations rather than equating configured cache size with resident memory.

Kagi fresh discovery and bounded Scry context/schema/exact-identity query artifacts are under `var/native-scouts-20261031/state-resources/`. Initial `arxiv.papers` schema request failed because the relation is now `academic.papers`; corrected using live schema. Search results establish discovery, not technical claims. New SQLite documentation HTML and its retrieval/hash/reading-depth manifest are retained in `~/paperbin/oracle-native-20261031/state-resources/`. ## Incremental extraction and decisive rejection cases

First inventory state owners with read/write call sites and reset behavior, separating immutable corpus data, tenant durable records, session records, request-local scratch and derived caches. Make the first interface `TurnInput -> Candidate + ContextDelta`, not `export_engine()`. Implement semantic deltas for native reader and arithmetic before moving all legacy state; exercise a cross-provider sequence and arbitration-loser case. Then replace one Python owner at a time, retaining explicit coverage for unsupported owners. Finally permit reusable tenant-neutral native workers; keep unknown Python owners in tenant-bound processes. Preserve old bounded adapters as a reversible comparison path until independent cases establish the replacement.

Counterexamples must include equal labels for different QIDs; equal numeric IDs in different namespaces; tenant A/B using identical session names; image replacement with reused IDs; one session's timeout after consuming a pending rewrite; a losing candidate that guessed the right number; contradictory units/offset conversion; rounded imported values treated as exact; restart after commit before response delivery; eviction followed by “it”; explicit topic reset; and an unsupported final correction following a previously valid number. Worker TEMP tables must be cleared even on cancellation; partial cleanup should poison the lease rather than hand another tenant stale rows.

The revisable-reasoning scout adds independent support IDs, ledger revisions even when atoms are unchanged, negative-guard/coverage dependencies, and AND/OR justifications. Cache keys must include evidence/theory revision, image, coverage scope, unit schema and provider semantics version. Ordinary graph reachability cannot substitute for justification semantics. Evict derived caches freely; preserve the committed ledger or declare the context unavailable. Cache misses must not become negative knowledge.

Whole-process benchmark proposal: same admitted U8/native corpus and fixed worker counts, with 1/10/100/1000 retained sessions and separate active concurrency sweeps. Measure host plus all children/guardians/solvers, summed PSS/private memory, cgroup current/peak anonymous and file charges, RSS separately, allocator live bytes, SQLite cache/TEMP use, faults, FDs, startup/first-answer and p50/p95 latency. Compare warm OS cache against fresh owned process without dropping shared caches. Include churn, long selections, cancellation and mixed provider sequences. The target model is shared image cost + bounded worker scratch + measured small session cost; a linear giant per-session slope rejects the design. No invented throughput target or result is claimed. Readiness alone cannot reveal the peak during image admission or Python startup.

The reader/compiler scout identifies an essential existing boundary: identical rendered answers may be delivered while differing selections suppress Previous updates. Commit a referent only when all successful admitted readings agree on canonical identity and evidence, retaining qualifier scopes, attribute positions and temporal precision. A derivation identifier is not an entity identifier.

Dependencies: data-execution must define stable image/coverage references; reader/compiler must emit typed answer identity; revisable reasoning must expose revision/support lineage; composition owns winner selection and commit boundary. Open questions are which Python owners remain outside the current schema, how much history is semantically required, and whether tenant-wide serialization should eventually narrow to session scope after all shared mutation is removed.
