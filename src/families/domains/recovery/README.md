# Fixed domain recovery leaf

This leaf is under design for D59. No native recovery factory is installed yet.
The bundle, request, display and gate remain separate consumers awaiting their
actual checks. Shared role/profile changes belong to the recovery/host owners.

The agreed closed pairs are `quantities/1` with `domain-request`, and
`quantities-runtime-refinement/1` with `domain-output`; both use
`Controlled_Recipe` and the actual installed executable pin. Requests are
nonassertional and have an empty raw sequent. Outputs retain
nonempty typed **runtime-refinement** material: the complete certified target,
ordered full condition propositions, accepted universal implementation/model/
display contracts and actual same-request output. This is not a kernel sequent
proving the computed answer. The role decoder must reject a substituted kernel
evidence snapshot, a dummy theorem or an empty output slot. Root approved this
assurance distinction and recovery/host agreed the exact pairs. Shared decoder
qualification and native leaf integration remain prerequisites.

The fixed factory consumes authenticated committed material and the current
checkpoint. It validates the closed role, original parent/request/output slot,
all slot digests, native image and executable pin. Assembly's static generated
matcher must compare the original request, goal, subject, operation, whole
immutable template, source and condition references, and semantic/executable
generations. A final match requires exactly one complete set of materials for
each protected accessible owner. Digest equality alone is not this match.

Only that factory constructs `protected_domain_request`. A condition selector
extracts its saved record from this opaque request; callers cannot supply a
replacement identity or proposition. Staging rebuilds the actual G/P receiver
and Q source through the shared recovery pool. It parses the full original
declaration in that receiver, checks native equality, source owner/span, role,
generation and managed ancestry, then creates an opaque `checked_condition`
owning its graph/source leases. Staged P developments are deliberately not live
until fragment installation; ordinary `Domain_Conditions.prepare` cannot stage.

One restore batch interns each authenticated old condition identity. Reuse must
match the entire proposition, role, original source identity/bytes/encoding/span
and native receiver correspondence. Conflicts fail. Standalone declaration
sources retain their own Q/source lease before graph pruning. The common graph
and source fragments install atomically; condition identities are not inserted
into a new generic global numeric map.

After installation, the private condition constructor consumes its checked
witness once. It rechecks actual development liveness and exact installed
source/generation correspondence, retaining consumer leases before publication.
The preserved condition identity comes only from the checked witness. Request
reconstruction then compares the complete original input, template, contracts,
source ownership and ordered conditions. Output reconstruction runs the fixed
implementation for that same restored request, checks the saved output/target
and rebuilds the checked display/gate association. It never replays a charged
user operation or allocates a new ticket to manufacture historical authority.

The fixed SourceDomain ingress additionally reconstructs the actual qualified
source cell and its unit/conversion correspondence, retaining both source and
domain guards through charge, publication, rendering, recovery and Forget. A
naked extracted Domain request cannot authorize a source-derived answer.

Required actual fixtures include changed full proposition under the same ID,
same declaration text in the wrong receiver, wrong source/span/role/pin, repeated
or conflicting checked-witness consumption, complete shared-condition interning,
retained sibling/evidence leases after producer disposal, explicit source
invalidation, selective Forget and a real host restart without workflow replay.
