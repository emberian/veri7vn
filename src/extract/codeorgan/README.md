# Code from examples

This route builds small Python functions from a fixed library of integer and
integer-list operations. It accepts at least two literal input/output examples
and checks every one with a program evaluator generated by Isabelle. It never
executes request text, user definitions or stored source.

For example:

```
Write a function f that returns the sum of squares of even numbers:
f([-4,-1,0,2,3]) == 20, f([]) == 0
```

The answer shows a candidate function and says that it matches the supplied
examples. This does not establish that the examples specify the intended
function on every input. When matching named programs disagree on additional
bounded observations, the route asks for distinguishing examples. Agreement
on those observations is not a proof of equivalence.

The library contains integer addition, subtraction and multiplication; list
concatenation and truncated pairwise addition/multiplication; sorting,
reversal, deduplication, integer maps and filters; sums, products, lengths,
maxima/minima and simple predicates. A program uses one argument, or combines
two arguments, then applies at most four named operations. Explicit numeric
phrases also support adding/multiplying each item, threshold filters, taking
and dropping a prefix. Deduplication keeps each item's **last** occurrence,
matching HOL `remdups`; the displayed Python implements that order. Maxima and
minima of an empty list are undefined and cannot pass an empty-list example.
Booleans are distinct from integers; emitted functions enforce this with strict
input-type guards. Function names that shadow globals used by the templates
are refused. Pairwise operations truncate to the
shorter input, as Python `zip` does.

The recognizer deliberately refuses unsupported qualifications and malformed
examples. Initial limits are 32 examples, one or two arguments, 256 integers
per list, input integers with magnitude at most `10**30`, description parameters
with magnitude at most 1000, and 256 candidate programs. Native prefix
evaluations enforce intermediate integer magnitude at most `10**240` and
intermediate lists of at most 256 items for this synthesis transport. String operations,
recursion, arbitrary control flow and learning new library functions are not
implemented yet.

`CodeOrgan.thy` defines the language and its evaluator. `check_every_example`
proves that an accepted nonempty example set contains only inputs whose
program evaluation equals the stated output. Separate theorems prove
sequential composition, argument lookup, sorted output with unchanged
multiplicities, deduplication with unchanged members, and an even-square-sum
pipeline for every integer list. These statements concern the typed program
and supplied data. English recognition, JSON framing, Python rendering and
external runtime checks remain untrusted.

Build and run:

```sh
tools/dev/remote-build persvati src/extract/codeorgan Veri7vn_CodeOrgan \
  --expect 'VERI7VN_CODEORGAN PASS theorems=16 oracles=0'
src/extract/codeorgan/build.sh /absolute/path/to/passed/receipt.json
python3 src/extract/codeorgan/answerer.py \
  --kernel var/codeorgan/bin/codeorgan-kernel
python3 src/extract/codeorgan/check.py
python3 src/extract/codeorgan/check_consumer.py
python3 -m unittest discover -s src/extract/codeorgan -p test_lifecycle.py -v
```

The frontdoor follows the answerer JSON-line contract. Its checked-computation
packet contains the exact program AST, every example, native results and
displayed source so the dispatcher can independently replay and compare them.
The native checker itself accepts typed program JSON, not natural language.

No code-organ specialist panel is shipped under `upstream/root/specialists/`.
The authored route checks, reserved numerical cases and direct Oracle7 code
chat comparison are scoped evidence, not a specialist scoreboard result.
