# Retained example-guided candidates

`Mathematics_Proposals` and `Retained_Mathematics` use actual `math_expr`, `math_eval` and independent `math_value`. Compatible retained forms precede bounded fresh enumeration; every form is rechecked on new samples. Equal sample vectors do not collapse programs. Expected/actual optional values retain undefined arithmetic, and sample agreement never becomes universal proof.

Nonpublishing evaluation takes an immutable library and returns new candidates/observations without persistence callbacks. Retention explicitly creates a managed artifact revision; it does not activate a capability. Tests distinguish later rejection of a constant, identity reuse, changed contexts, empty evidence and baseline isolation.

## Source-owned application

`growth/native/growth_request.ML` consumes live source owners and actual D43 candidates. It resolves a definition in the retained native context, checks source dependencies and fixed mathematical constructors, and parses original typed sample slices. Parameter closure yields kernel equalities and actual prepared `M.request` inputs. Missing parameters refuse before execution; division by zero remains an actual `None` result.

The assembly must charge each sample through the installed math worker. Output association checks sample index, expected term and `M.belongs_to`, preserving mismatches and undefined results. Request release drops prepared inputs/native terms while immutable observations remain nonauthoritative data. Context keys and numeric IDs alone cannot supply native ownership.
