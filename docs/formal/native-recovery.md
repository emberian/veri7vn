# Native recovery correspondence

The public named theorem profile reconstructs the actual canonical public image
with `Managed_Provenance.public_image`, retrieves a theorem through the approved
producer, and runs ordinary kernel-consequence admission. It does not reuse a
private context that happens to print the same proposition. The saved full native
sequent is compared to the fresh accepted theorem, including ordered hypotheses,
premises, sort constraints, flex-flex pairs and exact typed target/proposition.

`Native_Recovery_Check` issues an opaque correspondence witness only after checking
the protected committed capability, every named-slot SHA256 digest, workspace and
association/generation identity, exact public context closure, registered recipe,
complete sequent and the ordered role partition of all durable premise IDs. Saved
claim/target/interpretation/evidence/generation/premise IDs remain durable metadata;
the actual native generation and theorem are freshly constructed. The fixed
projection is canonical bounded YXML and has no theorem deserializer.

The context closure includes the host-installed actual boot build manifest and
the approved baseline theory ancestry. Export requires exact native theory
identity with that captured baseline. The host must derive the manifest from the
actual immutable heaps and source/build/code setup loaded into its resident
process. Calling the privileged image installer with an arbitrary string does not
qualify this trusted startup boundary. A matching theory name supplies no such
policy. This is trusted image qualification, not a theorem about SHA256,
Isabelle ML, host storage, or compiler correctness.

No recovery proof obligation is discharged by the codec or digest checks. Logical
authority comes from the fresh kernel theorem and C02 admission. Exact identity
reassociation and current-checkpoint authorization remain separate checks: the
runtime must compare the rebuilt generated evidence against the latest authority
checkpoint, recover all accessible retained evidence, and atomically install the
whole set without executing historical commands. Forget/revoke and release must
remove retained native roots as well as artifacts.

The registered profiles implement canonical public named facts and bounded chains
of actual managed source definitions. The private profile exports constructor
lineage, exact source bytes/encoding, durable source-owner IDs, byte offsets, plain
bindings and embedded-token flags. It replays from the exact installed baseline,
re-admits the resulting definition theorem, and compares the complete saved native
sequent and dependency list. Unsupported binding scopes fail qualification.

A pre-provenance source checker parses the protected committed context closure
and issues opaque restored-source tokens. A restoration batch shares one fresh
physical input per workspace/source ID and rejects conflicting byte meanings.
The managed producer consumes these tokens without accepting raw caller IDs.
The shared restore graph owns that source batch. Association and retained-context
leases keep their actual logical ancestors and construction sources alive. Only
unreachable source inputs are forgotten; a released fact cannot invalidate another
live fact or a refined-family consumer that retains the same context.

The public/private native reconstruction and shared-context tests have passed
their scoped native session. Full source
development replay, bounded proof reconstruction, family certificates and
executable build reconstruction still require their actual producer/context
closure. Unsupported material fails closed; these profiles do not complete the
full recovery requirement.

The staged graph implementation separates canonical construction owners from
logical aliases. One alias/native generation wrapper represents each saved
context ID; distinct historical IDs can share the same actual theory while
retaining distinct wrappers and original logical parent IDs. Canonical cache
owners receive new reserved internal IDs only during the atomic checked batch
install. Their IDs never enter restored claims or managed artifact edges.

The fixed kernel correspondence checker issues an opaque numeric identity
fragment only after all native comparisons succeed. The shared allocator merges
this with independently checked refined-family fragments, validates all conflicts
and identities, and changes its numeric map and staging flags once. Reverse identity uniqueness
also covers existing live associations in the workspace. Actual whole-context
retirement removes its generation mapping, so recovery can reassociate a saved ID
only after the previous physical context has retired. The compile-time checker
functor does not verify arbitrary ML implementations: only pinned fixed checker
instantiations belong to the trusted image. Ordinary source/worker input cannot
install a checker or instantiate privileged ML.

Typed retained-context leases let other native families borrow the actual checked
generation without depending on the lifetime of a kernel descriptor. Their owner
must drain its jobs and instances before releasing the lease. Context leases
retain logical ancestors and shared construction nodes. Releasing
a fact removes its lease; unreachable aliases, construction subtrees and source
inputs are pruned. The multifact test reconstructs x = 42 and y = x in their
shared actual ancestor/child theories, then composes their native definition
theorems with `Thm.transitive`. It also checks same-ID wrapper sharing, distinct-ID
wrapper separation, shared-context identity, and release isolation. The graph and canonical-ID migration passed `Veri7vn_Native_Recovery_Tests`
in `a6f87ab8d4ebe987/attempts/e843016747534eb191f6c2c01fd591ee`
(8 seconds, theory 0.356 seconds). Assertions also cover retaining the actual
context after the last kernel descriptor releases, then removing its identity
on final retained-context release. The enclosing build failed unrelated
Bundle/Development targets; this receipt does not establish the service or
refined Math consumer integration.

D40 adds a shared protected input pool to the restore transaction. Fixed kernel
and Math profile checkers acquire leases only from their opaque checked source
witnesses. A saved workspace/input ID selects one actual input owner; conflicting
bytes or encoding reject, and equal bytes under different IDs retain different
owners. The completed native image exposes no raw saved-ID pool constructor.
The static checker functors are privileged image assembly, not verification of
arbitrary ML modules.

Input base ownership, independent consumer leases and invalidation are separate.
Managed native units retain their actual input leases. Pool closure drops staging
base ownership after transfer; normal consumer release leaves other consumers
alive. Forget invalidates access immediately, while physical bytes are cleared
after all owners drain. A pool entry with no pool lease may retain a nonowning
input handle while a native unit owns its bytes; it cannot keep payload bytes
alive after the last literal owner releases. Numeric input identity mappings are
removed only on actual physical disposal. Generation and input fragments install
in one checked atomic identity update. The coherent D40 component check passed all selected Registry, CoreChecks,
NativeRecoveryTests and SourceTokens sessions in
`1ec15fb468670a61/attempts/a4cec1ebd31b408f8beb7f782b7d03a6`
(stable 77.146 seconds; recovery 6 seconds, theory 0.444 seconds). The recovery
assertions include the exact composed proposition, source-map publication guards
and physical owner reuse/release. This establishes the native component path;
the service Math ancestor consumer remains a separate integration check.

A checked private association can retain a logical ancestor through
`retain_context_for`. Lookup starts from that association's exact verified head
and follows only its saved logical parents. It cannot expose another association
in the same batch, an internal cache node or an arbitrary workspace mapping. The
returned typed lease keeps the actual ancestor wrapper and identity alive after
the private descriptor releases. A refined Math consumer must independently check
its approved boot/context/code relation before borrowing that ancestor. This
ancestor consumer extension is not covered by the earlier D40 receipt.

The finite managed expert profile uses `veri7vn-managed-expert-replay/1` inside
native-kernel `Controlled_Recipe`. Its inert topological DAG records public roots,
exact source definitions and managed expert replay nodes. Each replay node binds
ordered source import locators to its saved logical parent IDs and records the
actual owned full-input source ID plus original byte offsets. The recipe selects
an exact canonical theorem name and index. It transports no ML, method evaluator,
plugin or theorem object.

Qualification and restoration both call the original `P.replay_source` producer
and `P.named_theorem`, then compare target, complete proposition, ordered
hypotheses/premises/sorts and flex-flex pairs through ordinary C02 admission.
Private named facts use this controlled profile even though their producer
retains a theorem name. They cannot be classified as public-image facts merely
from that name. The shared graph reconstructs actual approved parent contexts
once and gives each saved logical ID its own checked alias wrapper. Source and
context identity fragments retain the same atomic installation boundary.

Expert replay construction runs outside the graph's synchronized state update.
A builder temporarily owns typed leases for reused logical contexts and the
actual checked source inputs, constructs fresh nodes interruptibly, then validates
its snapshot version and parent/source liveness in a short commit. A concurrent
release or graph change rejects that construction; cleanup releases its fresh
nodes and temporary holds without retiring another owner's contexts. The
read-only per-batch active replay count carries no source details or authority;
targeted tests use it to observe an isolated construction before cancellation or
concurrent release. Those tests explicitly fail if replay already finished, rather
than reporting such a run as interruption coverage. These new checks await their
first native leaf result.

A fixed managed construction scope closes the asynchronous return boundary:
`P.publish` records each fresh development in its caller's scope before unmasking
interrupts. Recovery holds the scope before starting replay. A failed build or
lost graph commit aborts only that scope's fresh nodes; successful graph commit
transfers ownership and closes it. Qualification always aborts its scope after
checking, because it publishes no reconstructed development. This scope is an
opaque lifetime mechanism, not a callback, provenance assertion or saved-ID
constructor. It also covers public and primitive-definition qualification.

Builder holds are bounded by the requested graph: indexed canonical nodes and
saved aliases select at most two holds per requested construction node. They are
released in one batched decrement and one graph prune/source cleanup. Recovery
does not inflate every retained association's lease or repeatedly prune the whole
workspace for each hold.
