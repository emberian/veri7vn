# Behavioral qualification

The first fragment compares two source-owned mathematical recipe candidates through the fixed interpreter. It measures finite domain examples, not the complete upstream `workbench/exam.py` routing exam. General-question/identity interception remain unmeasured; requiring either makes this fragment insufficient. Structural `named-native-export-structure/1` qualification is separate.

## Panel and measures

The retained UTF-8 panel contains 1–32 newline-terminated rows, four tab-separated fields each, at most 65,536 bytes:

```text
exact<TAB>4<TAB>1<TAB>[(0,2::rat)]
decline<TAB>-<TAB>-<TAB>[(0,0::rat)]
unknown<TAB>-<TAB>-<TAB>[(0,3::rat)]
```

`exact` requires rational equality; `decline` requires clean refusal; `unknown` is unscored. Timeout, unavailable instance and projection failure are measurement failures. Canonical numerators/positive denominators are bounded to 2,048 bytes; each bindings slice to 16,384 bytes. Parsing consumes the original slice.

Both subjects receive identical ordered rows. Metrics retain scored/unknown counts, correctness, false/wrong assertions, clean refusals and failures; rational comparison uses cross multiplication. Baseline runs before candidate. Integer-microsecond intervals include preparation, execution, projection and cleanup; median is the upper middle sample. Cold/warm state is unclassified. These measurements establish neither general correctness nor latency bounds.

## Actual consumer

`Veri7vn_Behavioral_Recipes` consumes opaque `Veri7vn_Growth_Attachment_Fn` candidates, original panel leases and the actual mathematical interpreter. Interrupted results retain completed rows and a completed baseline side. `behavioral_panel.ML` owns exact-source parsing; `behavioral_metrics.ML` records and reduces observations.

D55–D58 require one qualification reservation binding panel, candidates, observer context/code, dependencies, run policy and exact goal/slot. Durable exposure/start precedes the worker; all paired execution uses that paid attempt and `QualificationOrigin`, without a second pure charge. Started-but-unfinished held-out evaluation restores as interrupted, never reruns. Development evaluation is distinct from fresh held-out evaluation.

`capture_result` accepts only the observer's opaque result and retains actual rows/timings, original panel/slice, subjects, definitions/generations, work, executable manifests, interpreter contract and paid context. The service must authenticate that context against the actual start. Timing restoration uses the captured run, not remeasurement: TB-03 covers attribution, TB-04 measurement, TB-02 interpreter execution.

Native fixtures cover unknown/failure misclassification and real sibling recipes; compilation and paid service/recovery/workbench/publication integration remain unqualified. There is no constructor from caller receipts or decoded rows to a completed result. See [recipe attachment](../growth/retained-candidates.md) and [qualification roles](updates.md).
