# Behavioral qualification

`named-native-export-structure/1` compares canonical export names and complete
native sequents. It does not measure routing improvement, false assertions,
interception or latency. Structural qualification and semantic admission remain
separate from the behavioral observer described here.

The first behavioral fragment compares two actual, source-owned mathematical
recipe candidates through the fixed native mathematical interpreter. It is not
the full operational specialist exam in `upstream/workbench/exam.py`. In
particular, general-question and identity interception are **unmeasured** until
an actual candidate routing attachment exists. Requiring either criterion makes
this fragment insufficient; an empty panel never gives a passing zero.

## Source panel

The panel retains its original UTF-8 source owner and exact slice. Each row ends
in a newline and has exactly four tab-separated fields:

```text
exact<TAB>4<TAB>1<TAB>[(0,2::rat)]
decline<TAB>-<TAB>-<TAB>[(0,0::rat)]
unknown<TAB>-<TAB>-<TAB>[(0,3::rat)]
```

The first row expects the rational value 4/1. The second requires a clean
decline; asserting any rational is a false assertion. The third has no known
answer and remains unscored even if a candidate asserts a value. An execution
timeout, unavailable instance or failed projection is a measurement failure,
never a successful decline. Expected values are attributed example data, not
admitted world truths.

Numerators use canonical decimal notation (a minus sign for negative values),
denominators are positive canonical decimals, and each is bounded to 2048 bytes.
The panel contains 1–32 rows in at most 65536 bytes. Each original bindings
subspan contains at most 16384 bytes. The fixed bindings parser consumes that
exact subspan; the panel does not regenerate an equivalent-looking term.

Both subjects consume the same ordered rows. The metrics preserve rational
equality by exact cross multiplication, scored/unknown counts, correctness,
false assertions, wrong asserted values, clean refusals and measurement failures.
The correctness gain is restricted to domain rows. Timing is a per-side elapsed
measurement in integer microseconds; the median is the upper middle sample, as
in the upstream exam. These finite measurements are not application latency
budgets, tail-latency evidence or a general performance claim.
The first/warm state is explicitly unclassified. Baseline and candidate execute
serially, in that order, and each interval includes application preparation,
execution, result projection and resource cleanup.

## Execution and lifecycle obligations

The mathematical recipe attachment must retain the actual build candidate,
native definition, native generation, universal definition/closure bridge and
fixed interpreter executable. An executable locator or matching export name
does not create this attachment. The growth owner supplies this association;
the behavioral leaf must consume its opaque application and actual output.

The service must bind the original panel owner, both candidates, profile,
observer context/code, source dependencies, run policy and exact goal/slot to
one qualification reservation. It durably records exposure and start before
calling the fixed worker. All paired execution is paid by that attempt. Its
output uses the same `QualificationOrigin`; there is no second `ExecutePure`
charge and no caller proof/evaluator callback. This is D55–D58 composition.

Repeatable development/regression evaluation is distinct from a fresh held-out
evaluation. Imported sender history cannot establish recipient freshness.
Crash/interruption spends the started held-out attempt; restoring Started
without a result yields interrupted state. Restore does not rerun measurements,
effects or charges. Failed results retain observations and leave active
publication unchanged. Observer context is the shipped observer's actual
semantic context, with both subjects explicit dependencies.

## Current evidence and consumers

`behavioral_metrics.ML` implements bounded recording and policy reduction.
`behavioral_panel.ML` implements retained-source parsing with exact bindings
subspans and cleanup on failure. The native fixture refutes unknown-as-correct,
failure-as-decline, false-assertion regression and unmeasured-as-passing mistakes.
Compilation is delegated to the shared build steward; no pass is claimed here.

The actual growth attachment, paid worker, durable qualification role,
restart/failure preservation, workbench comparison and publication consumer must
be connected and checked together. Until then these leaf components are not a
completed behavioral qualification or full operational exam.

The leaf now consumes `Veri7vn_Growth_Attachment_Fn` and the actual mathematical
interpreter in `Veri7vn_Behavioral_Recipes`. It retains both opaque candidate
leases and the original panel, and preserves completed rows plus the last
completed baseline side when interrupted during the candidate side. The native
recipe fixture builds actual sibling candidates and compares their results.
This fixed native worker is ready for the service's paid-start integration; the
fixture itself does not claim that durable service join.

`capture_result` accepts only that observer's opaque completed result. It creates
an owned original run source containing the actual rows and timings, exact panel
source/slice, subject projections and native generations, definitions, work,
observer/interpreter executable manifests, interpreter contract sequent and
paid-run context. It retains both candidate leases and the original panel lease.
The wrapper must authenticate that context against the exact paid start before
using the capture in `TestObservation` and its checkpoint. Merely possessing the
bytes does not create a qualification or a theorem.

Historical elapsed time must never be remeasured during restoration. A future
checked role may restore its attribution only through the original captured run
source and authenticated checkpoint, under the explicit trusted measurement
boundary (TB-04), with durable attribution covered by TB-03. The actual
interpreter association retains TB-02's existing code/runtime assumptions.
Without that association, historical timing is unavailable. There is
no constructor here from decoded rows or caller-created receipt bytes to a
completed result. The recovery factory and durable role remain shared integration
work, separately from preserving the original temporal capture.
