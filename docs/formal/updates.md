# Dependency updates

`PackageUpdates` inspects exact source revisions and computes conservative consumer
invalidation. Its source edges denote complete snapshots, including absence,
ranking and aggregates; they are not lists of positive witnesses. Transitive
consumers are included. Request reuse compares all pinned components and exact
session, clock origin/reading, source-event and configuration observations.
A repoll cannot replace an event identity or advance its event time.

Package inspection reports SHA changes without exposing source bytes. Classification
of native source changes must come from the native build service. Non-source
content changes request data/recipe revalidation and do not request an executable
rebuild. A changed native session setup conservatively requires compilation.
These are plans, not admitted candidates or generated authority events.

Actual publication must consume the generated qualification reservation/start,
measured qualification and StageQualifiedPublication pipeline through the existing
single durable writer. The generated previous-slot check provides atomic replacement;
historical pins retain their meaning. Protected general package-publication ingress
and D43 typed native build artifacts remain integration dependencies. This module
does not synthesize either from caller-created metadata. Replacement does not imply
revocation. D44 Forget must invalidate authority and registered native/private roots
before storage erasure can count as complete; ManagedDrafts.forgetStorage is only a
storage receipt. Selected transfer continues through TransferPolicy's exact graph
fingerprint, private-ancestry choices and attributable exposure artifacts.

## Replacement structural observation profile

`native_package_qualification.ML` implements
`named-native-export-structure/1`. An opaque retained baseline contract
captures canonical export names and full native sequents. The candidate is
measured against those expected values, including proposition, target, hypotheses,
premises, sorts and flex-flex pairs; same-count wrong propositions reject. Both
sides refer to real managed native owners and kernel admission. The closed service
retains candidate leases through measurement and durable role ownership. Count is diagnostic.

This observation is deliberately structural. Sibling native contexts can attach
different definitions to the same constant name while printing equal sequents.
The profile returns no permission for semantic-generation reuse, cached claims,
context transfer, behavioral equivalence or performance claims. A changed-definition
fixture exercises that distinction. New meanings require their own semantic pins;
a preservation criterion requires a checked context/constant correspondence or
native bridging theorem. Unsupported qualification criteria must refuse rather
than silently consuming this structural observation.

The profile currently supports nonempty theorem export lists only. This restriction
belongs to this observation profile, not source authoring or native build: zero-export
candidates remain legal. Assembly integration must durably reserve/start the fixed
qualification before measurement, register private baseline-contract/observation
roots for Forget, and bind the exact resulting observation to its generated
TestObservation target and installed criterion policy. That integration is pending.

The closed update owner additionally requires a distinct candidate and retained
baseline and an expected current slot equal to that baseline candidate. This
prevents manufacturing an expected update contract from the candidate being
qualified. Initial publication is not implemented by this baseline-backed profile;
it requires an independently owned expectation or another explicitly supported
policy. Assembly must compare the expected slot with actual current authority,
consume the exact generated started command, and only then call the owner's
one-use worker start. Measurement runs outside the state-owner lock. Cancellation
joins the worker before releasing its private expected-contract/observation roots.

## Initial logical-export admission criterion

The separately approved `native-export-admission/1` profile has no baseline. Its
intended evidence is limited to an immutable manifest export intent captured
before replay, the exact candidate source closure, and the actual canonical
C02-admitted exports with their assumptions, extension policy and provenance.
It does not invent another theorem from a TestObservation. It establishes no
regression, behavioral-quality, performance or old-generation reuse claim.

`initial_admission_*` pure helpers use distinct typed names/result records,
Development mode, `baseline_artifact=None`, baseline-free policy, and initial
slot compare-and-swap with `publication_previous=None`. These helpers are data
constructors; until the opaque pre-build intent producer and protected service
join are installed, they do not activate anything. Empty-export developments
remain valid nonassertional source artifacts and do not gain an active logical
capability merely by passing source replay.


## Protected observation recovery

The initial and replacement observations have distinct protected recovery roles,
not native theorem roles. Their bounded codec preserves complete candidate pins,
context, private IDs, dependencies and full native snapshot vectors. Parsing is
inert. The checked factories consume actual retained candidate leases, verify
current checkpoint membership and the installed qualifier image/code closure,
and deterministically remeasure the corresponding fixed profile. Recovery does
not reserve, charge, expose, replay execution or start a worker again.

The factories preserve the saved observation identities. A saved native semantic
ID must already resolve to the restored candidate generation; a numeric ID alone
cannot retag a development. Qualification material is available from the first
durable evidence attachment, before the later qualification/publication stages.
That permits restart between stages without treating an unfinished publication as
active. The role registry, Frame adapters and final durable service connection
remain shared integration work; the standalone codec is not that connection.

## Pending requests and observer pins (D55, D57)

Before a measured observation exists, qualification uses distinct request roles:
`native-export-admission/1` with `initial-qualification-request`, and
`named-native-export-structure/1` with `update-qualification-request`. Their explicitly versioned payloads retain original context, allocated observation identities, candidate
pins, dependencies and a unique request-child slot. That slot is separate from
the active package publication slot. Replacement requests also retain the original
baseline contract snapshots. Neither role contains a successful measurement.

The fixed checkpoint verifier derives Prepared, Reserved or Started from the
actual current child and exact reservation. Typed reconstruction preserves those
identities without preparing a new request, measuring, charging, exposing or
starting a worker. Prepared and Reserved owners can continue only through the
current generated guards. A Started request with no committed observation is
restored as interrupted; it cannot measure again for free. A later attempt needs
its own current-authority reservation and charge. Missing or duplicate native
request-child material must refuse startup in the shared role dispatcher.

TestObservation semantic pins identify the fixed shipped qualifier observer
context, constructed from the exact executable code theory and fixed profile.
They do not identify a candidate theorem. Candidate and baseline native generation
IDs remain explicit protected subject dependencies, with their exact export
snapshots and publication bindings. This allows a Build→qualification composite
to seal its observer meaning before the candidate exists, without guessing the
future candidate generation. Old candidate theorem/cache pins are never retagged.

Checked request/result witnesses expose observer-ID fragments only after complete
image, code, profile and checkpoint correspondence checks. Startup must collect
these privately and install them atomically after all members succeed. The fixed
qualifier installation owns a committed observer mapping for the session lifetime;
individual witness release must not remove a mapping shared by other requests.
Candidate leases and current authority remain independently enforced.

Earlier candidate-generation observation snapshots are not silently reinterpreted
as observer-generation snapshots. Restoration must match the exact protected role,
code/image closure and dependency vector; incompatible old payloads refuse and
require an explicit migration or fresh qualification.

Measured result wire format is version 2, with reconstruction markers
`initial-qualification/2` and `update-qualification/2`. Initial pending request wire format is version 2 with
`initial-qualification-request/2`; replacement pending request wire format is
version 1 with `update-qualification-request/1`. Both carry the unique request slot separately
from the publication slot; mismatches reject. Result version 1 is deliberately
not accepted as a version 2 observer-context observation.

A composite Build→initial-qualification request uses the same initial request
role with an explicit `template` or `bound` variant in version 2. The template
owns a leased actual prepared BuildRequest, its original immutable export intent,
exact Build request/goal/slot/execution plan, fixed observer context and already
allocated qualification IDs. It contains neither a native candidate generation
nor a measured result. Source replay and BuildRequest reconstruction happen in
the build owner; restoring a template never executes that build.

Only a durable-acknowledged native output lease from the exact original Build
slot may bind the template. The adapter checks its complete source/manifest/
parent/profile/setup/intent association, original intent handle identity and
execution plan, then adds the actual subject generation while preserving every
qualification identity and immutable reserved Build edge. An unrelated candidate
with equal-looking exports cannot bind it. Prepared templates restore through the
actual BuildRequest owner first; bound requests restore through candidate owners.

Initial request version 1 is explicitly refused, because no deployed producer
published it before the template/bound distinction was introduced. It must never
be interpreted as a template. Update request version 1 remains bound-only. The
native unit fixtures exercise before-Build reconstruction, exact-output binding,
after-Build reconstruction and interrupted qualification; durable ack authenticity
and complete checkpoint-child membership are additional shared service checks.

Fixed role exporters consume actual leased measured owners, bound pending owners
or unresolved templates. They capture canonical native snapshots and exact manifest
fields and retain the owner independently until the durable writer finishes.
Replacement exports use the baseline contract captured by the original native
owner, rather than constructing a new expectation from the candidate. Request
material associates with the unique child slot; measured material associates with
the observation evidence ID. Both have an empty raw theorem-sequent slot because
they are scoped observations, not kernel theorem roles. The returned artifacts are
inert: only the existing authenticated store/current-checkpoint path can commit
and later reconstruct them through the corresponding fixed checker.
