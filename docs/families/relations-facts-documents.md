## Algorithms and meaning

`Relation_Query.relation_values` filters a pinned population, remdups values and classifies Absent/Unique/Multiple. `indexed_lookup_refinement` equates subject_bucket lookup with direct lookup. `query_relation` distinguishes unavailable source, failed guard, incomplete snapshot, missing/ambiguous entity and result. Current entity ambiguity is stricter than upstream convergent-answer behavior. `observed_relation_rows` retains valid observation provenance. `Relation_Join` independently characterizes two-edge paths over one population; its new proofs are pending, and it is not a registered operation.

`Relation_Source_Import` consumes shared source_batch four-column s,p,o,lit. It preserves NULL/literal bytes and arbitrary natural IDs; any malformed row rejects the entire batch (`malformed_row_rejects_whole_batch`, `decoded_rows_preserve_length`). `incomplete_batch_never_unique` prevents manufactured uniqueness. `SnapshotRelationQuery entities property` has independent `structured_relation_snapshot_meaning`; acquisition refinements retain matched manifest, original versioned bytes, actual decoded batch and attach_batch observation. Completeness refers only to declared selected materialization.

`Ordered_Facts` chooses the original first matching required/excluded-feature rule under narrative→gate→block→question guards, retaining typed value/sentence/reference. `Literature_Facts` has three representative source rules: Ishmael narrator, Ahab's Pequod, Austen authorship; narrator wins overlap, bare title is not authorship. Feature assumptions are not regex correctness.

`Document_Quotation` retains exact half-open bytes, document/revision, route/date and optional author; invalid/expired input rejects. `Document_Request` additionally pins identity/revision against independent document_span_meaning. `Source_Fact_Observation` pairs the selected guarded rule with its exact source quotation; unavailable selected source cannot fall back. Literal/reference/historical deliveries remain nonassertional; history retains original result/part/scope/completeness. These additions await native checks and managed original-document association.
