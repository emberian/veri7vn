# The specialist folders, linted

Every specialist manifest under `upstream/root/specialists/` was read by
`tools/lint/specialist-lint.py` on 2026-10-17. For each folder it checked the manifest
fields, the panel's shape and the scorer import; ran the counts in the shipped verdict
file through the verified exam gate (the HOL definition of exam.py's six criteria,
exported to SML and compiled with MLton); and matched the manifest's routing cues and a
sample of its own held-out questions against the live pre-route folds of the shipped
head, from the fold catalogue `audit/folds/folds.json`. Nothing under `upstream/` was
written and no organ was run.

Reproduce:

    python3 tools/lint/specialist-lint.py --all --aggregate docs/lint/specialists.md

Inputs: fold catalogue `/Users/ember/dev/o7vn/audit/folds/folds.json` (132 live pre-route folds of the 253, the other 121 being
dead copies; 0 guard patterns skipped as uncompilable in Python), gate binary `/Users/ember/dev/o7vn/var/gate/build/gate_check`
(built by `tools/gate/check_verdicts.py --extract --compile` from session `Veri7vn_Specialists`).
A fold's guard matches are calibrated against 100 generic core-panel questions; a guard
that fires on 90% or more of them is reported as universal, not as overlap.

## What stands out

- The workbench's own exam (exam.py) cannot run ANY shipped panel: 304 panels are flat
  lists of items tagged with `split`, and exam.py calls `panel.get(split)` on what it
  loaded (a list has no `.get`); on top of that 304 panel paths carry the
  `__ORACLE7_ROOT__` placeholder, which exam.py joins onto the folder as written.
  The exam is written for new folders authored in the workbench, not for the drop.
- Every shipped verdict measured the lane cap on a SAMPLE of about 400 of the 924 core
  questions. On that sample the formula's cap is 5; on the full panel exam.py uses, 9.
  The three gate disagreements (rel-novels, rel-graphicartists, rel-translators) are all
  specialists that took 6 general questions. The release ADMITTED them, so it was looser
  than exam.py's cap of 9, not stricter; only the gate run on the sample's cap of 5
  rejects them.
- None of the shipped verdict files carries a files_sha, so exam.py's own status check
  would mark every shipped specialist "changed since its exam" and keep it out of the
  model (305 verdict files seen, 242 carried every count the gate needs, and not one of
  those has the hash).
- 161 manifests set accept.context_regex to the empty string (all relation readers):
  exam.py compiles the key when present -- the empty pattern matches EVERY text, so their
  in-domain declines are in-context everywhere, identity questions included.
- 5 manifests contain a raw backspace in accept.context_regex (JSON \b decoded to
  U+0008 instead of the regex word boundary): the pattern can never match, so no
  in-domain decline of those specialists is ever accepted.
- 163 panels have no must-decline item at all (valid: false), so no false-yes was ever
  measured for them; exam.py refuses to run a held-out set with fewer than 2.
- The 7 versioned folders (-v2/-v3) point store.path at predecessor folders that did
  not ship, and 13 folders carry no verdict of any kind.
