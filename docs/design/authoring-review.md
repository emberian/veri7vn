# Authoring, migration and handoff

An author owns one development: meaning, language, implementation, sources, examples,
obligations and deployment. The [installed workshop](../tutorials/installed-source-workshop.md)
provides the current entry point; [acceptance](../product/ACCEPTANCE.md) defines the
complete loop. The design below is a requirement, not proof all controls exist.

## The product an author owns

Package source is durable/editable; releases seal built closure; deployment selects
qualified generations; workspace keeps private drafts, connections and history.
Failed experiments leave the previous release usable. The author can inspect a
result's reading, assumptions, source, execution and evidence without reconstructing
implementation history.

## Canonical editable representation: native theory with approachable commands

Canonical `.thy` commands express family recipes with expert HOL/ML available under
its privilege policy. Forms patch owned source spans against a known revision;
expert blocks remain intact. Generated native definitions are derivatives. Sidecar
inputs retain one owner and source maps. Independently editable JSON semantics would
create drift; an obligatory separate DSL would limit native growth.

## Authors develop intentions; machinery handles routine obligations

Recipes supply reusable representation/correctness laws, language patterns and
negative cases. Authors choose roles, formula/query, domain and examples. Tools
elaborate, check and search routine obligations. Hard obligations stay visible.
Restricting `sqrt(x*x)=x` to `x>=0` differs from changing its meaning to `abs(x)`.
Duplicate entity rows require alternatives/clarification or explicit selection,
not silent deletion. Correct computation cannot establish intended reading.

## Oracle7 intake becomes family development, with accountable repairs

Retain pinned source/config/data, actual dispatch/override path, inputs/outputs,
exceptions, guards, state/effects and observed examples. Static import does not run
Python. Differential comparison uses authorized isolated legacy execution and an
identified environment; absent stores remain absent. Shared relation/fact patterns
should become recipes, but identical signatures do not prove semantic equivalence.

Constrained extraction requires stated translation obligations. Otherwise specify
and implement natively from reviewed behavior. An opaque wrapper remains an adapter.
Each deliberate repair records a short old/new example and reason. Migration includes
routing, arbitration and session/workbench composition, not only manifest counts.
Replacement data identifies itself rather than claiming original-corpus parity.

## Admission, qualification and deployment are three separate decisions

A draft has independent build, semantic admission, empirical qualification and
activation records. Typical loop: edit → build → diagnose → evaluate → release →
activate. Tests can run before proof. Activation requires promised assurance,
mandatory family/interference tests, dependencies/effects and resource policy.

Use repeatable regression for development; fresh holdouts support claims requiring
freshness/generalization. Bind panel/split/scorer identities and durably consume
eligibility before exposure. Aborted runs may already be exposed; import/log deletion
cannot manufacture freshness. Legacy thresholds are named comparison profiles,
not universal laws. A scorer is executable evaluation code, not theorem authority.

## The complete author loop

Opt-in gaps retain unresolved readings/blockers and private origin. Selected questions
become examples with unknown expectations, not automatic ground truth. Repairs are
reviewable patches. Profiling attributes interpretation, retrieval, search, execution,
checking, rendering and startup/admission. Optimizations create a candidate plus
preservation obligation; activation leaves old requests pinned under current access.
Human and synthesis proposals use the same lifecycle. Retained logical results,
executable improvements and search experience remain separate.

## Sources and local state are workspace bindings, not secret package payloads

Packages declare source interfaces; workspaces bind local files, corpora, tools or
sensors. Snapshots record selection/mapping/origin; jobs have configured/running/
stopped/failed/retired lifecycle. Configuration cannot relabel prior observations.
Event/receipt clocks, quality, units and calibration remain per sample.
Discovery/testing/requalification require actual effect authority. Credentials stay
in host secret references. Feedback proposes versioned reading/routing changes;
default activation is reviewed, and undo creates another revision.

## Persistence, forgetting, restoration and transfer

Local history has explicit ephemeral/retention settings; gap journaling is opt-in.
Temporary recall and sensor windows are configurable policies, not theorem constants.
Retirement stops new use/acquisition while retained history may remain. Revocation
cancels dependent work and access; Forget additionally removes managed source,
examples, summaries, learning and cached/context roots. Curated copies appear in
impact preview. Status records contain no private snippets. External actions/copies
and forensic erasure are outside managed guarantees.

Restore checkpoints/associations without re-executing questions/actions. Historical
recall quotes its original scope/time. Export selects public source/examples/docs
and reproducible closure; private transcripts, feedback, bindings, caches and
credentials are excluded by default. Preview omitted dependencies and rebuild/run
limits. Import stages/inspects/builds/qualifies before activation; sender receipts
must be re-associated with real native objects.

## UI, CLI, Film and code experimentation

Offline browser and CLI share versioned engine operations, current revisions and
source diagnostics. Expert editing opens actual package source. Bundled UI technology
is replaceable; no second semantic server is implied. Authenticated loopback operations
need origin/token protections.

The scratchpad retains generated code, toolchain/input identity and test observations.
Executing arbitrary generated code requires a real isolation backend or explicit
trusted-code profile; `python -I` and subprocesses are not sandboxes. It remains an
artifact until admitted through the appropriate implementation route.

Film preserves local truthful HTML explanation and supported browser-produced WebM,
with conditions, source/evidence links and companion records. Narration must not
erase qualifications; generated images are decoration. Remote media/public registry
adapters are optional controlled effects whose handoff scope is explicitly decided.

## Handoff and remaining genuine choices

Ship offline runtime/heaps, UI/CLI, recipes, editable examples and selected data/solver
packs. Complete create → diagnose → repair → profile → activate without hidden
implementer commands or unexpected builds. Check macOS/Linux independently. Include
one substantive composed/search-driven development, source repair, transfer/recovery
and coverage map. License/publication, optional network adapters and unavailable
corpus replacement remain explicit scope decisions; widget/tactic choices are
engineering work. See [recipient rehearsal](../handoff/recipient-rehearsal.md).
