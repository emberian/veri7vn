# Adversarial architecture checks

A viable specialist environment must preserve useful behavior and its actual
assurance across interfaces. These discriminators constrain the
[architecture](../ARCHITECTURE_PROPOSAL.md); they are not passing-test claims.

## Judgment

Native openness, generated authority and finite typed execution are compatible only
if the actual consumers share their bridges. Reject independent acceptance engines,
name-only callback attachment, opaque-wrapper migration and universal semantic tags.
The [proof ledger](../../project/PROOF_OBLIGATIONS.md) names formal versus trusted
boundary obligations; [acceptance](../product/ACCEPTANCE.md) adds product behavior.

## Architectural invariants

1. **Privilege:** supported declarations, speculative worker returns and trusted
   native plugins are different interfaces. Arbitrary ML can bypass host policy;
   opaque constructors do not sandbox it. Plugin installation changes runtime TCB.
2. **Authority:** actual generated transitions govern accepted publication/state.
   Native objects and host observations have explicit association contracts, not
   a generic unexplained `adapter_correct` assumption.
3. **Composition:** operations have native types, guards, representations and
   outcomes. Shared libraries factor repetition without erasing affine/log/frame/
   NULL/calendar laws. Bulk values stay native; no per-element term serialization.
4. **Migration:** separately record preserved/repaired behavior and actual assurance.
   Pinned SQLite observation differs from formal SQL semantics; neither licenses
   unrelated owned algorithms. Inventory paths are not independent proof projects.
5. **Growth:** authoring and search share canonical development/lifecycle. Catalogue,
   pipeline and enumeration synthesis retain distinct proposal logic. Admission,
   qualification and activation are independent axes.
6. **Commit:** authoritative local visibility is transactional; external handoff can
   remain uncertain. Restore records, not requests. Current authority applies to
   late workers; forgetting tracks managed reads/derivatives, not textual matches.
7. **Proof scope:** quantify over actual finite signatures, enabled rules and
   concrete bridges. Empty-interface theorems cannot cover new operations. Interpretation
   is relative to declared language, adoption to explicit premises. Semantic pruning/
   selective reuse require additional proofs; exact identity/pins are the baseline.
8. **Deployment:** resident native authority, bundled heaps and compiled values
   support offline core execution/search. Logical fuel needs real process/time/memory
   controls. Alternate backends follow measurement and the same refinement contract.

## Interface review rule

Before consumers freeze, agree native privilege, operation linkage, claim/outcome
algebra, commit/recovery, dependency/retention and bundle/worker boundaries. Keep
optimization backend, widget selection, exact cache organization and measured budgets
replaceable. A refuted claim needs a true useful replacement connected to consumers,
not merely a lower acceptance threshold.
