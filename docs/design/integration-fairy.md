# Resident workshop integration

This is an implementation record, not acceptance evidence. The installed baseline
and the current source remain distinct.

The first consumer is the actual managed workshop: import a native development,
Build, inspect the captured failure, repair the source explicitly, Build again,
close the resident process, reopen both results, and Forget one result without
destroying the other. `tests/integration/workshop/check.scala` compiles the actual
production Scala source inventory and runs that workflow against RuntimeService.
It supplies no mock native bridge, persisted acknowledgement, recovered source or
artifact constructor. Its stock-policy boundary example exercises native source
replay; it does not claim activated specialist execution or Oracle7 coverage.

## Production joins

The parent service's copied Build integration was behind the owning fragments.
The refreshed fragments retain independently acknowledged output owners, preserve
original source and terminal diagnostics, and use the exact comma-delimited host
protocol. They also expose the checked Build restoration functions to the parent.

The production launcher previously always passed `None` for BuildWorkspace, even
though direct workbench tests supplied a working adapter. RuntimeMain now reads
the installed native capability announcement through the host's strict reader and
passes the existing ResidentBuildWorkspace over the same managed source store.
The workflow regression invokes the real launcher after closing the first resident,
so a test-only adapter cannot conceal this missing product connection. The native
Build announcement now names the actual propose/poll dispatcher branches; the
assembled dispatcher and complete workflow still await execution qualification.

The parent source now joins those functions into the existing aggregate restore
transaction. Build, kernel evidence and later Search must share one physical input
pool and one rooted native recovery graph. Each factory checks an authenticated
committed material; the parent installs their identity fragments once, then retains
the actual native owners before closing construction batches. The authority owner's
complete restoration check remains the final gate. No saved numeric ID constructs
a theory, theorem, source owner or executable permission.

The original first Build profile selects `DevelopmentOnly`. A successful candidate
therefore says that the controlled source replay succeeded; it does not establish
package activation. The existing initial package qualifier accepts named logical
exports and rejects executable locators. Its structural update observer explicitly
does not license semantic reuse across sibling contexts. Connecting execution must
respect those distinctions rather than describing an artifact ID as deployment.

## Remaining semantic joins

- Candidate-only restoration after Cancel needs the original control capsule owned
  by the candidate itself. Pairing it with a required active request is insufficient
  for D74. The Build and recovery owners are migrating that capsule.
- Scope restoration needs authenticated child subsets, exact aggregate completeness
  and shared-header equality. Copying every sibling source into every capsule would
  violate selective Forget.
- The host requires restoration wire 4 with two inventories. The parent now emits
  that shape only after an early generated supported-profile guard. It explicitly
  rejects retained SessionLocal rows, effect observations and original effect
  requests, including pending source registrations. Three negative HOL lemmas
  accompany the guard. Full typed session/effect recovery remains unimplemented in
  the parent; an empty source inventory does not stand for those consumers.
- Search's retained proof context is independent of a live execution request.
  Parent integration must preserve that distinction and the exact source capsule.
- Package admission, qualification, activation and executing changed capabilities
  are still separate consuming paths; this workflow does not close those gates.

Root owns the task ledger, decision entries and commits. Native and Scala execution
remains serialized through the build steward and `tools/dev/check-native`.

## Converging user journeys

The workshop joins authored native developments to retained candidates. The next
cross-path use is logical-export admission followed by Search in that actual
admitted context. A candidate ID alone is not a Search context, and a qualification
observation is not the theorem evidence for the package's exports. Updates owns an
opaque native context view over real qualified and candidate owners; Search will
consume that view while the single parent authority checks current publication.

The other complete paths are original question to retained Search proof and
history, session source to adopted native result and historical recall, and actual
MCP execution to retained source observation and restart without reinvocation.
Each uses the same source custody, Scope boundary, rooted native verifier graph,
authority transaction and cleanup barriers. Family-specific native factories keep
their actual evidence checks. The parent integrates their typed associations and
advertises only the joined dispatcher paths.

A shared unresolved design point is typed source inventory after disposable
request derivatives disappear. An untyped WorkspaceShared retained row cannot be
recognized as a literal by its shape: unrelated native generation rows have that
same shape. An authoritative source discriminator inside existing managed
retention is under review; it must preserve shared Math input lifetime and use
actual authenticated native material to recover bytes. No schema change or
row-shape classifier has been installed for this proposal.

These are preparation failures, not a completed workshop workflow.
