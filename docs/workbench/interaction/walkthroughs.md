## Additional source-ownership and diagnosis walkthroughs

- Reader recipe exposes key/result columns, snapshot selection, conflict/adoption policy. Editing proposes source and coverage obligations; it never edits a second semantic database.
- Concurrent expert edit r4→r5 makes the old form proposal stale. Preserve unsaved text and expert lemma; reparse/review current source. Invalid development leaves active r3 usable.
- New inventory data reuses the same reader/bundle, creates a source version and invalidates snapshot consumers. A competing row defeats uniqueness. New carrier/kernel requires separate executable qualification.
- Ambiguous Mercury product/room retains both typed entities and original spans. Choosing one records a decision; another reading's blocker stays scoped.
- Budget-stopped multipart search retains independent accepted parts and unresolved dependents. Feasible witness/bound/unknown optimality differ; a candidate artifact is not an accepted dependency.
- Forget recalled conversation propagates through temporary reader, subject cache, examples and learned derivatives; pending publication is denied. Restore reveals missing history without replay. Unknown actions reconcile separately.
