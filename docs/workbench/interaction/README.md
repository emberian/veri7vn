# Workspace interaction design

Design requirements under C01/C03/C04, D12/D20–D29; actual availability is in [client](../client.md) and [recipient operations](../../reference/recipient-operations.md). The offline prototype `design/workbench/index.html` has thirteen fixture-driven walkthroughs, no backend or external assets. Regenerate with `python3 design/workbench/render.py`; validate with `python3 design/workbench/check.py`.

## One understandable workspace

Questions, Packages, Sources, opt-in Gaps, Scratch and History share one workspace. Results offer Inspect, Improve, Explain/export and contextual Correct. Improve opens the same canonical development used by Build. Header distinguishes editable revision, immutable release, deployment and private bindings.

Separate readiness labels **Math check**, **Example checks**, **Use** correspond to admission, qualification and deployment; precise states/policies live in Advanced. An admitted reader can report conflicting sources, a useful artifact can lack proof and a qualified release can remain inactive. No universal verified badge collapses these axes.

Create chooses a supported recipe and editable example with domain/units or reader schema/ambiguity policy. Unknown expectations stay unknown; model-proposed answers remain proposed. Expert blocks stay accessible; unsupported syntax yields source-only editing, not destructive normalization.

## Canonical source editing and recoverable concurrency

Forms are read-only projections of native parsing: recipe, source span, revision and declarations. Changes propose exact source patches, obligations, meaning/domain effects and affected consumers. Apply checks revision, original bytes and current authority; generated fields never become a second editable semantics.

Use physical source mappings, not guessed UTF-16/PIDE offsets. Atomic multi-edits share one base. Concurrent expert edit shows base/current/proposed, preserving drafts; reparse before new proposal. Invalid development remains saved with diagnostics while active release stays usable. Arbitrary Isar/ML needs its explicit privileged policy.

## Closed author loop

1. Inspect a decline, result or gap with original reading/reason/scope. Collection is opt-in; draft expectations remain unknown until selected.
2. Create/import canonical source, retaining private origins and curated-copy choices.
3. Edit, inspect meaning and run examples. Supplying a premise, adopting source data and changing specification are distinct decisions.
4. Build/admit, then evaluate baseline/candidate with exact scorer/bindings, exposure and interference/resource cases. Abort consumes exposure but supplies no measured verdict.
5. Profile representative phases/resources; optimization creates a candidate and preservation obligation.
6. Preview exact release/binding/dependency closure; activate only through native authorization and durable ack. Old requests keep valid pins; rollback is a new transition.
7. Link feedback to actual result/reading/invocation; propose/evaluate/publish a policy revision or preserve the old one. Undo is another revision.

Square-root repair contrasts domain restriction and absolute-value specification. Conflict retains both rows; multipart area/paint/supplier retains each typed outcome. Prefixes show order/coverage. Ambiguity resolves before execution; safety guards block invocation while model/source premises remain conditional.

## Oracle7-original intake

Stage manifests/cards/panels/scorers/organs/source/exposure as bounded inert bytes. Reject traversal/links/duplicates/oversize safely. Preserve the upstream JSONL transfer defect as an intake repair requirement. Mapping compares original/proposed theory and preservation/repair decisions. Unknown Python requires a native port/bridge; trusted scratch observation is not a lift. Sender evidence is historical; recipient regression differs from fresh holdout.

## Private sources, effects and recovery

Packages declare interfaces; workspace bindings select targets and secret references. Configure/discover/preview/probe/start/stop/requalify are explicit operations. Show actual target, outbound data, schema/config, argument validation, retry/cancel policy and authority. Read-only annotations do not prove effect freedom.

Observations retain event/receipt/evaluation clocks, unit/config/quality/origin and coverage. Repolling cannot refresh event time; last-valid stale differs from fresh. Windows differ from deletion. Reconfiguration versions policy. Retirement blocks acquisition; revocation/Forget also deny dependent publication/access and remove managed payloads/derivatives through cleanup. Preview transcripts, examples, learned features, caches and pending work; curated copies need a choice. External copies lie outside managed erasure.

Recall quotes history; restore loads allowed typed state; execute-again creates new work. Lost acknowledgment requires inspecting existing operation identity. Unknown external handoff requires reconciliation, never automatic replay.

## Scratch and explanation export

Scratch retains editable code/tests/inputs/toolchain and exact observations/open obligations. Use “trusted code” unless a real isolation backend supplies more; `python -I`/temporary cwd are not a sandbox. Promotion proposes native development, not admission from tests.

Explain/export binds selected structured results and actual output bytes. Preview complete polarity/conditions/source/history/evidence and private closure. Local HTML preserves full detail; optional WebM links its companion rather than dropping premises. Preserve framing/selected turns/hidden-tab pause. Generated imagery is labeled decoration. Remote narration/registry calls require separate destination/payload authority; D16 controls inclusion.

## Accessibility, durable history and error treatment

Provide labeled keyboard controls/focus, field-associated announced errors and text status; do not depend on color or steal browser shortcuts. CLI retains typed partial/lifecycle structure and useful source locations. Distinguish transport success from accepted claim/effect success.

History distinguishes revisions, candidates, observations, releases and deployment commits. Source conflicts preserve text; build failure preserves active deployment; unavailable content shows non-content status. Refresh reads state without retrying work. Actual editor/screen-reader/recipient trials remain required beyond static [walkthrough checks](walkthroughs.md).
