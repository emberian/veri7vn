# Specialist engineering environment: completion criteria

ACC-01–16 define completion, not current passing status. Evidence must span [all coverage families](../coverage/README.md), the actual deployed consumer and the [G01–G08 cases](../review/PREIMPLEMENTATION.md). A theorem, adapter, arithmetic demo or family class cannot substitute for its missing product connection.

| ID | Required behavior | Acceptance evidence |
|---|---|---|
| ACC-01 Package ownership | One durable editable package joins meaning, language, sources, implementation, examples, obligations, performance and dependencies. Forms and expert Isabelle edit coherent objects. | Versioned schema; import/export/roundtrip; generated ownership; preserved custom edits and canonical contracts. |
| ACC-02 Authoring and inspection | Create, revise, inspect and run every supported family through shared UI/CLI operations. | Family workflow matrix; explicit Oracle7 preserve/repair/defer decisions; documented recipient rehearsal without implementer help. Automated tests do not establish human usability. |
| ACC-03 Diagnosis and repair | Failures identify reading, contract, unresolved condition and original source/proof span; repairs distinguish domain restriction from changed meaning. | Negative square root, ambiguity, conflicting rows, missing assumptions and exhausted search; reviewable new package revision. Search failure is not refutation. |
| ACC-04 Language fidelity | Declared rules produce typed scoped interpretations; ambiguity survives resolution; rendering preserves licensed claims. | Elaboration/renderer bridge, alternatives, paraphrase/context tests and coverage limits; no claim to prove mental intent. |
| ACC-05 Composition | Quantities, queries/search exchange typed values, retaining units, flags, failures, conflicts, conditions and effects. | Actual composition/refinement APIs; compatible-family matrix; Boolean-collapse and rounded-key regressions; justified incompatibilities. |
| ACC-06 Sources and observations | Record retrieval/extraction, snapshot, transformations, license and loss; reports differ from adopted premises. | Reproducible manifests/importer; missing-v2 disposition; existence/absence/uniqueness/count/extremum candidate-region dependencies. Replacement data identifies itself. |
| ACC-07 Change impact | Changes invalidate exactly the supported reuse guarantee; running work retains generation pins. | Competing-row insertion, evidence removal, assumption/contract change and concurrent update tests. Whole-generation invalidation is allowed initially; selective reuse needs proof. |
| ACC-08 Admission and assurance | Required theory, hypotheses, sources and implementation accompany every accepted definition/theorem/program. | Actual gate and invariants; hidden-hypothesis/oracle/axiom/context probes; no route bypass or world axioms from inconsistent rows. Kernel, refinement, authorized oracle and empirical observations remain distinct. |
| ACC-09 Deployed reasoning | Installed budgeted strategies support retrieval, application, simplification, splitting, counterexamples, conjectures, synthesis and refinement. | Multistep cross-capability goals, traces, cancellation/resource measurements from shipped artifacts; a fixed proof replay is insufficient. |
| ACC-10 Growth and reuse | Retain logical results, search experience and executable improvements separately; generalization creates obligations. | Persist/reload/reuse each category; admit vocabulary/abstraction/implementation; reject stale/failed candidates; account for all three Oracle7 synthesis mechanisms. |
| ACC-11 State and effects | Sessions, freshness, connectors, sensors and actions obey authority/commit boundaries; cancellation blocks late publication. | Connected model/runtime, interruption/temporal/session tests and local connector conformance. Privileged ML is not a generated-strategy sandbox. |
| ACC-12 Compilation and performance | Stage stable operations once; profile every request phase; optimizations preserve declared semantics. | Pinned workloads/toolchains; cold/warm/admission/update/tail/memory/evidence/cancellation measures; representative evidence-derived budgets, not toy speedups. |
| ACC-13 Deployment | Supported targets launch pinned prebuilt runtime/heaps/capabilities/indexes and support editing/search without surprise HOL-Analysis builds. | Clean launch/admission, dependency/license closure, update/recovery and reduced-runtime feature envelope; recorded OS/platform decisions. |
| ACC-14 Transfer and recovery | Share/import inspectable provenance without accidental private history/source export; failed changes preserve working installation. | Transfer diagnostics, fault recovery, rollback, rebuild and troubleshooting. Public/chain registry scope is separately decided. |
| ACC-15 Behavioral migration | Every manifest and reachable core/workbench operation has a disposition with evidence; defects are intentionally repaired. | Coverage ledger, valid upstream comparisons, independent negative/property checks and unavailable-source limits; opaque adapters are not completed lifts. |
| ACC-16 Maintainability and handoff | Recipient can extend, diagnose, profile/refine, package and deploy without original developers. | Versioned tutorials/reference/API docs/examples/build tools, independent rehearsal and tracked gaps. |

## Dependency order for parallel work

Investigate coverage/interactions alongside contracts. Agree shared representation/lifecycle interfaces before consuming them. Build families, clients, strategies and deployment against those seams; changes update their consumers. Integrate continuously; clean recipient rehearsal is the final composed gate, not the first integration test.

## Decisions that need early evidence

Use reviewed domain/runtime classification to choose languages/backends. Pin assurance/executable associations, source adoption, state/effect semantics, integrations and supported machines. Derive resource budgets from measurements. Missing provenance/data and untested usability remain explicit limits without blocking unrelated implementation.
