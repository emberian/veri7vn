# Remaining native runtime work

The native runtime already has shared indexed data, the pinned KQA program
vocabulary, bounded learned composition, durable language/query turns, release
admission, state retirement, resident extracted checking, private HTTP serving and
relocatable packaging. Optional graph, algebra, chemistry, scientific, dependency,
DNA and statistical operations run through that service. See the
[capability catalog](CAPABILITIES.md) for exact scope and evidence, and the
[migration map](MIGRATION.md) for upstream consumers that remain.

The destination remains the complete Oracle service: shared public resources,
compact private state and bounded active computation. No new shipped specialist
panel scores are available. Full Engine state migration remains; Mini integration
belongs to its hosting team. This is the live native development plan. The
[completed cycle](../../project/lanes/NATIVE-NEXT-CYCLES-2026-10-31.md) records
implementation and validation through the typed-host/packed-reader checkpoint;
the [publication record](../../project/lanes/NATIVE-UPSTREAM-CHECKPOINT-2026-10-31.md)
records what upstream has received. Dated lane reports retain historical evidence.

The current activity is source-grounded planning and documentation cleanup before
another implementation batch. No new build, panel result or feature is implied by
the work packages below.

### Conversation: settle authority before parallel implementation

Current `/query` uses the host journal and Engine generation binding; its native
reader is pure. Stateful `/invoke` operations use the core session/reply journal.
The Engine worker neither imports nor exports the full conversation, and its
protocol discards much of the finalized reply provenance. The existing scalar
bridge is an unconnected helper, not production context transfer.

Use the core session/reply transaction as the proposed authority for new covered
conversation turns. Preserve opaque Engine dispatch/uncertainty recording; do not
introduce two independent successful commits across databases. Before editing
runtime code, specify how durable dispatch, final reply/state commit and recovery
relate, how existing exact retry bytes remain available, and how `/query` and
stateful `/invoke` serialize against the same session revision. An old conversation
must not be silently adopted into a new release identity.

The reviewed recovery protocol is:

- New covered turns share conversation admission across `/query` and stateful
  `/invoke`, from snapshot acquisition until execution/commit cleanup completes.
  Core revision comparison remains the final guard; a lease alone is insufficient.
- Use an explicitly tagged request identity binding endpoint, operation,
  conversation and release. Preserve each admitted dialect's exact-body or typed
  command identity. Reusing an ID through another endpoint conflicts; it does not
  create another turn. Specify legacy cross-journal collisions before migration.
- Core commits the checked candidate session and the already bounded exact HTTP
  response bytes together. The host ledger records opaque dispatch and unresolved
  outcomes; it cannot independently commit a competing successful reply.
- Startup and retry consult authoritative core completion before classifying an
  unfinished host dispatch. Current `Journal::open` synthesizes interrupted replies
  eagerly and must change for this profile. Test crash after core commit but before
  host acknowledgement, as well as before/after Engine dispatch.
- Preserve old completed host replies for exact replay. Legacy Engine conversations
  without covered snapshots require reset; no implicit import or empty snapshot.
- Restore covered Engine state from committed state before another evaluation.
  Failed capture, oversized results or precommit failure after dispatch retain
  uncertainty and retire/poison mutated workers; they never authorize automatic
  reexecution of a possibly effectful turn.
- A lost commit acknowledgement does not prove the transaction failed. Consult
  core completion before poisoning/classifying the turn; replay committed bytes
  whenever they exist.

The first core seam accepts a checked candidate envelope, captured base
revision/identity plus exact captured state bytes (or their collision-resistant
digest), and exact response bytes. Its request-binding and legacy-replay
contract must be written with the host journal owner before either side changes.
Core refusals advance revision while preserving selection; applying that behavior
to currently pure `/query` is an explicit new-profile migration choice.
Acknowledgement, scalar clearing and consumption of pending interpretation need
explicit per-owner transitions; merely selecting a native winner must not consume
Python context.

The Engine protocol needs versioned restore/evaluate/capture on its serialized
executor, original finalized provenance and explicit owner coverage. Entity IDs
need namespace conversion, not label guessing. Quantities retain units and
precision. A committed result updates context only after arbitration; speculative
routes cannot commit independently. Missing owner coverage requires reset or an
explicit unsupported continuation, never an empty fabricated state.

Start with a read-only profile covering entity follow-ups, quantities/arithmetic,
pending conversion, acknowledgements and topic changes. Inventory every upstream
owner needed for those paths, including histories and module-global loans.
Teaching, files and external tools keep their existing uncertainty/reset boundary.
The acceptance journey combines a delivered entity and follow-up, a topic change
to an energy quantity, a cost calculation, acknowledgement and continuation after
restart. Choose actual admitted reader/organ questions before fixing route gold.
The general conversation migration remains a destination beyond this first profile.

### Reader: separate semantic admission from stage execution

`grammar.rs` currently adds numeric-slot units without using the operation's
literal domain; `program.rs` already distinguishes quantity, year and date.
Introduce one binding helper shared by recipe and expanded adapters. Units must
come from declared context, never whichever stored row happens to match.

Terminal Count currently exempts all entity stages from empty refusal, whereas
composed child viability independently requires nonempty children. Define ordered
stage obligations explicitly, including unused branches and omitted children.
Representation changes first preserve the existing policy. The separate semantic
change must state whether a zero counts the supplied snapshot or asserts a closed
source domain; missing attributes and incomplete coverage must not become zero.
Use independently specified tiny stores for date precision, compatible/incompatible
units, and a complete zero-result domain with a matching incomplete-source case.

Carry a workspace-scoped checked-operation handle and borrowed dependencies into
`LanguageWorkspace`; keep the existing Plan adapter and stage store. Reuse must
avoid Node cloning/JSON keys and repeated CTE construction. Stage metadata includes
nonemptiness and retained rows/bytes, counted from successful insertions with the
same duplicate and UTF-8 accounting rules. No handle crosses image, lease, Previous
selection or program-workspace boundaries.

Cache exact admission summaries in the existing immutable recipe/interner. Byte
counts depend on rebased dependency indices: test 9→10 and 99→100, Unicode escaping,
nested/repeated children, dead steps, equivalent splice shapes and cached failures.
A single cached flat byte total is insufficient. One owner integrates the shared
`packed_program.rs` exports; recipe and execution lanes agree on those seams first.
No second arena, cross-request stage cache or interpretation pruning is needed.

### Evidence: checked restoration before persistence machinery

The authenticated owner read validates all retained extensions, then deserializes
the chosen owner again; evidence solve/checkpoint reconstruct it again downstream.
`Workspace::import_with_control` already returns a reusable checked workspace.
Extend the owner boundary to carry inherited work/deadline/cancellation through
restoration, validate the selected owner once and pass its checked handle onward.
Keep other extensions' validation and release/schema/tenant/session checks.
Reservations must survive with the checked state; client payloads cannot mint it.

The current 128 limit covers revisions and all historical record IDs, including
withdrawn records. Separate active records, historical IDs, event/retry retention,
bytes and work in host policy. Keep full replay initially. A compact snapshot alone
cannot preserve forbidden ID reuse or old retry tokens; compaction needs a separate
specified retention contract. A checkpoint receipt remains a receipt.

A useful consumer is a supplied thermal model whose load/conductance measurement
is corrected, changing a temperature acceptance decision. Current observations
carry atoms, not typed measurements; add an explicit value/unit/target adapter,
complete model identity and numerical outcome/balance evidence. Conductance or
boundary-membership changes require preparation; load-only changes can reuse valid
factors. Alternative supports and coverage withdrawal must affect the decision.
Keep fresh solver execution as the reference. Persistent clingo or dataflow is
not required to deliver this consumer.

Prepared thermal factors and sequence searches have different validity contracts.
Share existing admission/lifetime conventions; do not create a universal prepared
object registry before a consumer justifies cross-request retention.

### Specialist delivery and release

Deliver a supplied-data modeling specialist over existing calibration and
binomial/Poisson operations. Preserve exact certificate checks and numerical
statuses, require explicit rows/model/exposure/uncertainty choices, and clarify
missing assumptions. Begin with a bounded supplied-data form; add language
bindings only where their interpretation can be checked. Do not widen the existing
statistics manifests merely because their arithmetic panels pass.

The retained statistics controls are correct on their shipped items but have a
negative admission verdict for family-wide lane leakage. Specialist pinning and
new model workflows are distinct fixes. Historical acoustics/networking fallback
false yeses are scoped reproduction targets, not confirmed current defects.
Trace current refusal ownership before patching; out-of-domain requests must still
fall through. A later space protocol should preserve the extracted SML and its
specialist pins rather than reimplementing it in Rust.

Produce a current Linux standalone artifact from a frozen source with the runtime
and six compiled provider profiles, explicit optional solver/Engine/extracted
configuration, and separately identified public resources. Reuse `package_host.py`,
`make_config.py` and descriptor derivation. Record source/toolchain/feature identity,
binary and catalog hashes, external Python/environment assumptions and a separate
state root. Qualify relocation, enabled-provider discovery/calls, selected specialist
controls, tenant separation and exact retry/restart once after source convergence.
Do not describe this as hermetic packaging or a new signed Mini release.

Upstream delivery stays separable: semantic Python fixes; optional providers and
consumers; execution/host tools; image/readers; explicit conversation owners.
Publication and adoption remain separate states.

### Dispatch and work retained beyond this batch

Safe initial ownership is reader literal binding, checked owner restoration,
modeling specialist/consumer, and release tooling. Stage execution and recipe
summaries follow the agreed checked-view exports. Conversation runtime/host and
Python adapter lanes follow the durable-authority decision. Root owns shared

checks and one justified composed comparison; do not benchmark each lane in a loop.

Deeper composition and relation/document stores, remaining Python owners, actual

## Shared-resource design constraints

One release owns immutable data and learned tables. Tenants own scoped durable
state; requests own bounded scratch. Worker/solver/model capacity belongs to the
host, not to each tenant. Cache identities include release and any private
overlay/authority. A complete Engine wrapped in PyO3 still owns its Python heap.

Use actual route traces: a static inheritance traversal is not Python C3 order.
Keep compatible library providers behind coarse contained interfaces until a
replacement covers their contracts. Retain public resources in admitted shared
mounts where supported; changing implementation language does not remove package
format or resource custody requirements.

Extracted SML is native code. Measure kernel work separately from process startup
and resident transport. Rust can search for candidates checked by extracted code;
the certificate must meet the theorem's actual coverage premises. Independent
Rust checks, numerical residuals and held-out empirical results describe different
evidence. None should acquire a generic `verified` label.

For nonmonotonic reasoning, first define which predicates are closed-world for
which tenant and snapshot. A missing public fact remains unknown. Answering
from every stable model (skeptical) and from some stable model (credulous) are
different operations; expose that distinction and the assumptions. No stable
model, a timeout and incomplete enumeration must remain distinct outcomes.
Retractions must invalidate affected conclusions and their explanations.

Readout probes deserve their own capability track. A probe may compute a useful
property we cannot otherwise calculate; it need not be restricted to routing
or candidate ranking. Register its task, representation/model versions, training
provenance, held-out accuracy, calibration and abstention behavior. Use a formal
checker when one exists, and otherwise expose the result as an empirical
inference with its measured limits. Freeze datasets against leakage before
optimizing or comparing representations.

## Evidence for promotion

Compare the same revisions, data, limits and independently adjudicated questions.
Separate algorithm, representation and language changes. Include checker,
conversion, IPC and durable commit cost; retain refusals and failed cases.
Measure offline manufacturing, readiness, phase-level CPU/allocation, cold/warm
conditions, latency distribution and sustained throughput. Include process-tree
private memory, extracted children, solver state and model workspace.

Use fixed capacity for mixed tenants; test heavy/light fairness, cancellation,
busy admission, switching, crash/restart and duplicate requests through the real
host. Never clear another session's caches to manufacture a cold run. A candidate
should improve useful coverage or material cost on its consumer workload without
an unacceptable regression. Report the exact tested artifact and variation.
The historical 18-versus-545 MiB KQA comparison is not a full-Engine claim.
